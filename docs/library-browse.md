# 音乐库分类与筛选（设计提案 v1）

> 2026-10-31。回答「音乐库除了搜索还能怎么找歌」：分类怎么分、筛选怎么叠、视觉上怎么读。
> 相关：[library-redesign.md](library-redesign.md)（页头/列头/排序/密度）、[chips.md](chips.md)（标识）、
> [genre-localization.md](genre-localization.md)（流派名）、[performance.md](performance.md)（查询预算）。
> 状态：**M0–M4 已实施**。

## 1. 问题与目标

### 1.1 现状

音乐库现在只有两条找歌的路：

- 搜索框（标题 / 艺术家 / 专辑的子串）；
- 音源筛选（单选）。

`LibraryState` 里只有 `query` 与 `sourceFilter`，`filteredSongsOf` 在内存里做这两件事；
数据库按窗口读 1000 首。流派、年代、格式、时长、有没有词这些事实都在 `Song` 里，
但界面没有任何入口。20k 首的库，读者想说「放点 90 年代爵士」只能打字。

### 1.2 目标

1. **两种读法并存**：找歌（精确筛选）与逛库（按类别看封面），不互相替代。
2. **分类可下钻**：流派 / 年代 / 艺术家 / 音源 → 点一个类别 → 看到这一类下的歌。
3. **筛选可叠加**：同一类内多选是「或」，不同类之间是「与」；生效的筛选以可移除的 chip 呈现。
4. **不牺牲密度**：筛选入口不常驻一排下拉框；默认窗口仍以列表/封面为主。
5. **不把库拉进内存**：筛选在 SQL 里做，窗口仍是 1000 首；分面计数单独查询、按需缓存。
6. **视觉是唱片目录，不是仪表盘**：用封面拼贴、等宽数字与计数表达分布，不做饼图/折线图。

## 2. 方案

### 方案 A：只做分面筛选

- 工具条加一个「筛选」按钮，打开右侧面板；面板里是流派/年代/音源/格式/时长/状态等分组。
- 生效后工具条下出现可移除的 chip；列表仍是唯一的浏览面。
- **优点**：改动最小；与 `LibraryState`/SQL 的改造集中；不新增页面型。
- **缺点**：仍然要「先知道要找什么」；没有「逛」的入口；流派/年代没有视觉存在感。
- **适用**：只想尽快补上筛选能力、视觉后续再说。

### 方案 B：分类视图 + 分面筛选（推荐）

- 视图切换增加第四档「分类」：列表 / 双列 / 专辑 / **分类**。
- 分类视图按区块展示：**流派 / 年代 / 艺术家 / 音源**，每块是带封面的卡片与计数。
- 点一张卡 → 进入该类别的歌曲列表（带面包屑与「返回分类」），筛选 chip 自动带上该类别。
- 工具条的「筛选」按钮打开分面面板，可在当前类别上继续叠加。
- **优点**：既有「逛」的视觉入口，又有精确筛选；不占侧栏宽度；与现有视图切换同一套交互。
- **缺点**：多一个视图与一套分类卡片；需要分面计数与封面拼贴；工作量中等。
- **适用**：本项目的紧凑桌面 + 以封面为识别线索的音乐库。

### 方案 C：左侧分类树 + 右侧列表（双栏目录）

- 在音乐库内容区左侧加 160–180 的固定分类树（歌曲/专辑/艺术家/流派/年代/音源），右侧是表格/网格。
- **优点**：分类常驻、切换快；接近传统桌面音乐管理器。
- **缺点**：900 宽时内容区只剩约 496，表格列被压到只剩标题；与「紧凑」目标冲突；侧栏已有 196 的全局导航，再加一层会显得重。
- **适用**：1120 以上为主、愿意牺牲表格列宽的场景。

### 2.4 已拍板（2026-10-31）

| 决策 | 选择 |
| --- | --- |
| 分类入口 | **两者都做**：第四档「分类」视图 + 左侧可折叠分类树 |
| 首版分类 | **流派 / 年代 / 艺术家 / 音源 / 语言 / 格式** |
| 筛选提交 | **每勾一项即时生效**（120ms 合并 + 查询令牌，避免打库风暴） |
| 与改版关系 | 与 library-redesign 的页头 / 列头 / 行尾 / 排序**同一批落地** |

## 3. 约束

| 约束 | 结论 |
| --- | --- |
| 平台 | Linux 桌面优先；900×600 仍要可用，1120×760 是舒适尺寸 |
| 数据量 | 目标 20k 首；库不入内存，窗口 1000；筛选必须在 SQL 层 |
| 现有结构 | `LibraryState` 已有 `query`/`sourceFilter`；`filteredSongsOf` 是内存过滤；排序提案见 library-redesign §5 |
| 性能 | 筛选应用 ≤ 100ms（20k）；分面计数 ≤ 150ms（面板打开时一次）；滚动预算不退化 |
| 视觉 | 暖黑纸面 + 朱红 + 宋体标题 + 等宽数字；不新增 token；不做仪表盘 |
| 依赖 | 不新增第三方库；流派名走 `genreLabel`/`genresLabel` |
| 范围 | 不改扫描器、音源适配器、播放器；不做多选/拖拽/列宽拖拽 |

## 4. 设计：分类视图 + 左侧树 + 分面筛选

### 4.1 信息架构

```text
音乐库
├─ 左侧分类树（可折叠，仅音乐库页）
│  ├─ 全部歌曲
│  ├─ 流派   Jazz / Rock / 电子 …
│  ├─ 年代   1950s … 2020s
│  ├─ 艺术家 按曲目数排序
│  ├─ 音源   本地 / Openverse / 档案库 …
│  ├─ 语言   zh / en / ja …
│  └─ 格式   MP3 / FLAC / OGG / M4A …
└─ 主区
   ├─ 列表（表格，默认）
   ├─ 双列（宽窗）
   ├─ 专辑（封面网格）
   └─ 分类（六类分段 + 卡片网格）
```

- **两个入口，同一份状态**：左侧树负责快速切换/直接筛值；分类视图负责看封面与计数。点树里的 `流派 → Jazz` 与点分类卡 `Jazz` 落到同一个筛选。
- 「分类」是**浏览入口**，不是新的数据页：点卡片后回到同一个歌曲列表，只是带上筛选。
- 面包屑：`音乐库 / 流派 / Jazz`；右侧「返回分类」回到分类视图。
- 喜欢、缺词、纯音乐不单独做分类卡：它们是**状态筛选**，放在筛选面板的「状态」组。

### 4.2 页头与工具条

在 [library-redesign.md](library-redesign.md) 的页头/工具条基础上只加两件：

```text
[☰] 音乐库  219 首 · 64 张专辑 · 9 个来源     [搜索……]  [筛选 2]  [最近加入 ↓]  [列表|双列|专辑|分类]
```

- **☰**：展开/收起左侧分类树；<1120 默认收起，<900 改为 overlay 抽屉（不挤压表格）。
- **筛选**：34 高按钮，右侧带生效组数的小圆标；打开右侧面板。
- 生效的筛选在工具条下方以 chip 行出现（仅在有条目时占高）：

```text
[流派: Jazz ×] [年代: 1990s ×] [来源: 本地 ×]              清除全部
```

- 排序、视图切换沿用 library-redesign 的规则；分类视图隐藏排序（分类有自己的顺序：按计数降序）。

### 4.3 分类视图

分类视图顶部是一条**六类分段**：`流派 | 年代 | 艺术家 | 音源 | 语言 | 格式`；一次只显示一类，
不把六组卡片竖着堆成一条长页。分段与左侧树同步。

| 分类 | 卡片 | 计数 | 视觉 |
| --- | --- | --- | --- |
| 流派 | 流派名（本地化）+ 2×2 封面拼贴 | 曲目数 | 拼贴取该流派前 4 张专辑封面；无封面用首字母块 |
| 年代 | `1980s` 大字（mono）+ 3 张封面 | 曲目数 | 年代数字是主角，封面作底 |
| 艺术家 | 艺术家名 + 圆形/方形封面 | 曲目数 | 取该艺术家最高频专辑封面 |
| 音源 | 音源名 + 类别色图标 | 曲目数 | 健康度小圆点（复用音源健康色） |
| 语言 | 语言名（本地化）+ 语言码 mono | 曲目数 | `zh / en / ja`；无语言标签归「未标注」 |
| 格式 | 格式名（MP3 / FLAC …）+ 文件图标 | 曲目数 | 从 `type`/扩展名归一；「其他」兜底 |

- 卡片高度约 96–112；1120 窗口每行 4–5 张，900 窗口 3 张。
- 卡片 hover：封面轻微提亮 + 右下角出现「播放全部」；点击卡片进入筛选后的列表。
- 分类视图不做分页；每类最多显示前 24 张 + 「查看全部」进入带筛选的列表。
- 排序：按计数降序；分段右侧一个「名称 / 计数」切换（P3）。

### 4.4 筛选面板

右侧 sheet（宽 340，覆盖内容区，不挤压列表），标题「筛选」+ 关闭；底部「清除全部」。

| 组 | 选项 | 语义 | 备注 |
| --- | --- | --- | --- |
| 状态 | 全部 / 喜欢 / 有词 / 缺词 / 纯音乐 | 单选 | 喜欢来自 favorites；有词来自 `has_lyrics` 或智能任务 done/disputed |
| 流派 | 本地化流派名，多选，可搜索 | 组内 OR | 读 `genres`，为空回退 `genre`；显示计数 |
| 年代 | 1950s–2020s，多选 | 组内 OR | `year` 为 0 不参与 |
| 艺术家 | 多选，可搜索 | 组内 OR | 只显示前 50 + 搜索；避免长列表 |
| 音源 | 多选 | 组内 OR | 替代现有单选 sourceFilter |
| 格式 | mp3 / flac / ogg / m4a / wav / 其他 | 组内 OR | 从 `type` 或 URI 扩展名归一 |
| 时长 | <2 分 / 2–5 分 / 5–10 分 / >10 分 | 组内 OR | 纯音乐与播客通常落在 >10 分 |
| 加入时间 | 最近 7 天 / 30 天 / 一年 / 更早 | 组内 OR | `dateAdded` |
| 语言 | 有语言标签的曲目语言，多选 | 组内 OR | `language` 为空不显示该组 |

- **语义**：同一组内多选 = OR；不同组之间 = AND；搜索词 = AND。
- **计数**：每个选项显示「当前其他筛选下」的命中数（分面计数）；计算一次、面板打开时刷新。
- **应用时机**：每勾一项即时生效。勾选状态先落 UI（乐观），查询走 120ms 合并窗口 + 查询令牌：
  连续勾选只发最后一次，旧查询返回时被令牌丢弃；列表在 1–2 帧内更新。
- **计数刷新**：选项计数在面板打开时算一次；每次筛选生效后 200ms 合并刷新一次，避免勾选时连打库。
- **清除**：组内「清除本组」；底部「清除全部」。
- **空结果**：列表显示「没有匹配的曲目」+「清除筛选」。

### 4.5 状态归属

| 状态 | 归属 | 持久化 |
| --- | --- | --- |
| 搜索词 | `LibraryState.query` | 会话 |
| 筛选条件 | `LibraryState.filter`（新） | 写入 `view.json`，下次启动恢复 |
| 分类视图当前类别 | 路由参数或 `LibraryPane` 本地 state | 会话；面包屑可后退 |
| 分类树展开 | `LibraryPane` 本地 state | 会话；<1120 默认收起 |
| 排序 | `LibraryState.sort`（library-redesign §5） | 写入 `view.json`，默认最近加入倒序 |
| 视图模式 | `LibraryPane` 本地 state | 会话 |

- `sourceFilter` 并入 `LibraryFilter.sources`；旧的单选入口保留兼容，但内部只认一份 filter。
- 不在页面里再存一份筛选；`setFilter` 在 controller 里改一次状态、查一次库。

### 4.6 左侧分类树

- 位置：音乐库内容区左侧，**浮在内容上**（overlay，宽 168），不占列宽；点 ☰ 打开，选完自动收起。
  这样每一页的内容起点仍在同一位置，表格在树打开时也不被挤窄。
- 只在音乐库页出现，不替代全局侧栏；树打开时有一层浅色遮罩，点遮罩收起。
- 结构：`全部歌曲 / 流派 / 年代 / 艺术家 / 音源 / 语言 / 格式`；展开显示前 8 个值 + 「查看全部」。
- 点击类型：分类视图切到该分段；点击值：直接进入筛选后的列表，树保持展开。
- 树、分类视图分段、筛选面板共用同一份 `LibraryFilter`；树不存筛选副本。
- 键盘：↑↓ 在树内移动，Enter 选择；折叠状态与选中值都有可读标签。

## 5. 数据与查询

### 5.1 模型

```dart
enum LibraryStatusFilter { all, liked, withLyrics, withoutLyrics, instrumental }

@immutable
class LibraryFilter {
  final LibraryStatusFilter status;
  final Set<String> genres;
  final Set<int> decades;
  final Set<String> artists;
  final Set<String> sources;
  final Set<String> formats;
  final Set<DurationBucket> durations;
  final Set<AddedWindow> added;
  final Set<String> languages;

  bool get isEmpty => …;
  int get activeGroups => …;
}
```

- 与 `LibrarySort` 同属 library domain；`LibraryState.filter` 是唯一来源。
- `filteredSongsOf` 保留为测试/缓存状态的兜底；生产路径由 SQL 返回已筛选的窗口。

### 5.2 SQL

- 基础：`songs` + `smart_lyrics_tasks`（状态）+ `favorites`（喜欢）。
- 流派：`EXISTS (SELECT 1 FROM json_each(songs.json, '$.genres') g WHERE g.value IN (…))`；
  `genres` 为空时回退 `json_extract(json,'$.genre')`。
- 年代：`(year/10)*10 IN (…)`；`year > 0`。
- 音源：`COALESCE(source_id,'local') IN (…)`。
- 语言：入库时把 `language` 归一（小写 ISO-639-1，认不出保留原值）写入 `songs.language` 真实列；
  旧库启动时一次性回填；`songs.language IN (…)`。
- 格式：入库时把 `type` / URI 扩展名归一成 `mp3/flac/ogg/m4a/wav/other` 写入 `songs.format` 真实列；
  旧库同样回填；`songs.format IN (…)`。
- 时长：`duration` 毫秒分桶。
- 加入时间：`date_added >= ?`。
- 状态：`liked` 用 `EXISTS(favorites)`；`withLyrics` 用 `has_lyrics=1 OR EXISTS(task done/disputed)`；
  `instrumental` 用任务状态。
- 排序在筛选之后；窗口 `LIMIT/OFFSET` 不变。
- 索引：`songs(year)`、`songs(source_id)`、`songs(has_lyrics)`、`songs(date_added)`、`songs(duration)`、
  `songs(language)`、`songs(format)`；流派先用 `json_each`，20k 下若超预算再加
  `song_genres(song_id, genre)` 物化表。
- 迁移：`ALTER TABLE songs ADD COLUMN language TEXT` / `format TEXT`；回填与索引在启动迁移里一次完成，
  失败不阻塞库（筛选退化为 JSON/URI 解析，并在日志里记一条）。

### 5.3 分面计数

- `AppDatabase.libraryFacets(filter)`：对每个组做 `GROUP BY`，返回选项与计数。
- 只在筛选面板打开时查一次；结果缓存到面板关闭；扫描/增删后失效。
- 预算：20k 首 ≤ 150ms；若流派计数超预算，改为「当前窗口计数 + 总数」并在 UI 注明。

### 5.4 分类视图数据

- 六类卡片：流派/年代/艺术家/音源/语言/格式；`GROUP BY` + 计数 + 封面样本（每类取前 4 个 albumArtPath）。
- 分类视图一次只查当前分段（不是六组一起），首屏 ≤ 150ms；切换分段再查。
- 封面样本只取路径，不读图；无封面用首字母/格式图标。
- 分类视图与筛选面板共用同一份计数缓存；扫描/增删后失效。

## 6. 性能预算

| 操作 | 预算 | 守 |
| --- | --- | --- |
| 应用一次筛选（20k） | ≤ 100ms | `library_filter_bench_test` |
| 打开筛选面板的分面计数 | ≤ 150ms | 同上 |
| 分类视图首屏（一个分段 ≤24 卡） | ≤ 150ms | 同上 |
| 滚动 | 不高于 D5 的 23ms/步 | 现有基准 |
| 行 element | 不增加（筛选不进行） | `row_budget_test` |

- 不在 build 里做筛选/排序/计数。
