# 音乐库改版设计（提案 v1）

> 2026-10-25。这一页回答三件事：音乐库现在为什么挤、改成什么样、按什么顺序落地。
> 相关：[conventions.md](conventions.md)（尺寸与字体）、[performance-row-design.md](performance-row-design.md)（行预算）、
> [chips.md](chips.md)（标识）、[architecture.md](architecture.md)（状态归属）。
> 状态：**M1a/M1b 已实施**（页头/工具条/列头/行尾/排序/双列）；分类与筛选见 library-browse M0–M3。线框稿见 [`mockups/library-redesign.html`](mockups/library-redesign.html)。
> 分类、分面筛选与左侧分类树见 [`library-browse.md`](library-browse.md)；两件事**同一批落地**。

## 1. 现状

默认窗口 900×600（`PlatformConstants.desktopWindowWidth/Height`），侧栏 196，
内容区 656。首屏高度账：

| 部分 | 高度 |
| --- | ---: |
| 页头 34 + 工具条 36 + 上下留白 20 | 90 |
| 播放底栏 88 + 下边距 12 | 100 |
| 列表（600 − 90 − 100） | 410 |
| **可见行数（32 一行）** | **12.8** |

在这个尺寸下逐项看，问题不是「哪一颗按钮丑」，是四层的归属都偏了。

### 1.1 问题清单

| # | 问题 | 证据 | 后果 |
| --- | --- | --- | --- |
| P1 | 页头一行塞六件东西 | 眉标「资料库」、标题、统计、视图切换、全部入队、在线搜索同处 34 高的一行 | 统计被挤成小字；「全部入队」看起来像第三档视图；窄窗先牺牲的是信息，不是控件 |
| P2 | 工具条没有分组 | 搜索限宽 420 后右侧整段空白；筛选只剩一个漏斗；刷新孤零零贴着右边缘 | 三个控件读不出是一组；筛选的含混（筛什么？）只能靠悬停 |
| P3 | 行尾是杂物抽屉 | 一行常驻 3 个动作（详情 / 红心 / 入队）+ 1–4 个无字事实图标 + 音源标 | 每行都有一排等权重的 11px 图标，标题反而不占主导；20k 首滚动时也是白付的 element |
| P4 | 没有列头，也没有排序 | 列表从第一行直接开始；歌与歌之间的列宽靠猜；库的顺序写死在 `_mergeResults` 的标题升序 | 读者不知道第二列是艺术家还是专辑；也不能按「刚加入」找歌 |
| P5 | 默认顺序不是「最近加入」 | `dateAdded` 已经存在、扫描时保留首次入库时间，却只被发现页使用 | 刚扫进来的歌散落在字母序里；「我昨天加的那首在哪」只能搜 |
| P6 | 单屏信息量少，且加不上去 | 12.8 行；900 宽时专辑列（阈值 820，行宽只有 656）根本进不来，事实列却在显示 | 想看的（专辑）没有，不想看的（格式/码率图标）有；宽屏也只是把同一行拉长 |
| P7 | 视觉语言不统一 | 红色眉标、28 高视图切换、36 高筛选、34 高按钮、11px 图标混在同一屏；音源品牌色 + 事实色 + 强调色三套颜色同时出现 | 页面读起来像「日志」而不是「唱片目录」；可点的地方反而看不出可点 |
| P8 | 扫描状态会推挤列表 | `LibraryScanStatusBar` 在列表上方插入 2–20px；音源失败时长期占一行 | 扫描时列表整体下移，滚动位置跟着跳；失败提示常年挂着，变成噪音 |

## 2. 目标

改版后按默认窗口验收：

1. **默认窗口 1120×760**（工作区不够高时按 92% 收敛），首屏 **16 整行**（现 12 整行）；900×600 仍然 ≥12 行。
2. **一屏至少两种读法**：列表（列头 + 排序）与双列（16 首 → 26 首）；专辑视图保留。
3. **默认按加入时间倒序**，选择可持久化；任何一列点一下就能排序。
4. **每行最多一个常驻动作**（红心，且它是状态）；详情与入队只在悬停 / 键盘聚焦时出现。
5. **行内不再出现事实图标**；音源只留一个标识。事实全部进详情面板。
6. **列头与行永远同一张网格**：`LibraryRowMetrics` 同时算列头与行，窄窗按固定顺序收列。
7. 不破坏 D5 预算：一行 element ≤ 160（现 162，去掉事实后应更低），滚动 p99 ≤ 16.7ms。

## 3. 视觉方向：唱片目录（The Catalog）

保留现有的「暖黑纸面 + 朱红 + 宋体标题 + 等宽数字」。问题不是这套语言，是它没有被执行到底。
改版只做五条纪律：

1. **一个页面只有一个大标题。** 删掉红色眉标「资料库」——标题已经说了。眉标只留给对象页（专辑页的「专辑」）。
2. **红色只标记「正在发生」。** 正在播放、当前选中、当前排序列。不再给页面眉标、来源图标或装饰描边。
3. **一行最多一个彩色标记。** 音源标识保留类别色；事实图标全部退场；红心只在已标时填充。
4. **数字全部等宽、右对齐。** 序号、加入时间、时长、统计数字走 mono；列因此有账本的秩序。
5. **控件同高同圆角。** 工具条里的搜索、筛选、排序统一 `controlDefault`（34）与 8 圆角；不再出现 28 / 36 混排。

颜色、字号、间距不新增 token；全部从 `CompactTokens` / `CompactTheme` 取。

## 4. 布局

### 4.1 页头（40）

```text
音乐库   219 首 · 64 张专辑 · 9 个来源                              [在线搜索]  [⋯]
```

- 左：标题（displayMedium 24 宋体）+ 统计（整行 mono 11，它是账目不是正文；分隔点用次要色）。
- 右：在线搜索（34，窄窗退化为图标）、`⋯` 菜单。
- 视图切换归工具条（4.2）：它改的是列表的读法，不是页面的身份。
- `⋯` 只放全库动作：`重新扫描全部音源`（扫描中禁用并显示进度）、`将当前列表加入队列`。
- **删除**：红色眉标、独立的「全部入队」图标、独立的刷新图标。刷新降级为菜单项 + 页头下的 2px 进度线；音源失败时菜单图标带一个小圆点。
- 统计在内容宽 < 640 时隐藏（先让位），在线搜索在 < 560 时退化为图标。

### 4.2 工具条（34）

```text
[🔍 搜索 …………………………] [全部来源 ⌄]        [最近加入 ↓]   [列表|双列|专辑]
```

- 搜索：吃掉工具条剩下的宽度，上限 680；不再把 420 之后留成空白。
- 来源筛选：写出当前值（`全部来源` / 具体音源），34 高，活动时用强调色描边。
- 排序：`最近加入 ↓`，34 高，只在列表 / 双列出现；专辑视图隐藏（专辑按名称自有顺序）。
- 视图切换：`列表 / 双列 / 专辑`，34 高，贴右边缘；双列是第三档（4.6）。
- 结果数：只有搜索或筛选生效时出现，放在排序左边，不重复页头的总数。
- 「全部入队」不在这里：它归页头的 `⋯`（4.1）。

### 4.3 列头（26）

```text
 #   标题                        艺术家               专辑              加入     时长
```

- 11px mono，次要色；可点列同时也是排序按钮（点击 = 设为本列默认方向，再点 = 反向）。
- 活动列：文字转 `onSurface`，箭头用强调色。
- 列头只写列名，不放动作：整库动作都归页头的 `⋯` 菜单（4.1）。
- 列头不滚动，和行共用 `LibraryRowMetrics`；收列时一起收。

### 4.4 行（32，不变）

```text
[#] [封面 24] [标题 flex 5] [艺术家 flex 3] [专辑 flex 3] [加入 56] [尾部 102]
 22     34         标题永远在         ≥480        ≥820        ≥760     音源 · 时长 · ♡
```

- **去掉** `TrackFactStrip`（存储 / 格式 / 无损 / 码率 / 直播事实）：这些在详情面板里已经有了，行尾只留一个 `SourceBadge`（18px，类别色，名字在 tooltip）。
  这改写 [chips.md](chips.md) 里「行内自动变成一个纯图标」那一句；落地时同步改文档与 `track_facts_test`。
- **尾部是一块 102px 的叠加区**，不是三列：
  - 静止：`[音源 18] [时长 44] [♡ 24]`，右对齐，行尾是紧的；
  - 悬停 / 键盘聚焦 / 正在播放：时长与音源淡出，原位换成 `[ⓘ 24] [+] 24 [♡ 24]`，红心钉在最右、不移动；
  - 这样既不常驻一列空位，也不因显隐改变任何列宽。
  - 红心**常驻**在叠加区最右（空心 = 未标，实心 = 已标；它是状态，不是第三个动作）。
  - 详情与入队**默认透明**；行悬停或获得键盘焦点时 120ms 淡入。焦点进入动作区时保持可见。
  - 正在播放的行与选中行始终显示三个动作。
- 时长右对齐、mono；加入时间 mono（`今天` / `昨天` / `3 天前` / `09-12` / `2024-05`），`dateAdded <= 0` 写 `—`。
- 序号列保留：它给左缘一个节奏，也承载正在播放的均衡器。32 行高、24 封面不变，密度已经到底，不再压。

### 4.5 断点

`LibraryRowMetrics` 以**行宽**（内容宽 − 两侧 gutter）判定：

| 行宽 | 显示 |
| --- | --- |
| < 480 | 标题 · 时长 · 红心 |
| ≥ 480 | + 艺术家 |
| ≥ 760 | + 加入时间 |
| ≥ 820 | + 专辑 |
| ≥ 1200 | + 格式 · 码率（P2，可选） |

默认 1120 窗口的行宽是 876：标题 + 艺术家 + 专辑 + 加入 + 时长全部在场。
900 窗口是 656：只到艺术家，但不再显示事实图标，右缘反而更干净。

### 4.6 多列：一屏更多歌

「多列」有两种读法，两种都做，但主次不同：

1. **同一行更多数据列**：4.5 的断点表，是列表的自然扩展。它让一行信息更全，不让一屏歌更多。
2. **一屏两列歌曲**：让一屏从 16 首到 26 首，是这一节要做的。

**双列视图**（`LibraryViewMode.columns`）：

- 视图切换第三档：列表 / 双列 / 专辑，位置见 4.2。默认列表。
- 行宽 ≥ 860（1120 窗口满足）才可用；更窄时第三档隐藏，若读者此前选了双列则回落到列表，但选择记着，窗口变宽就回来。
- 顺序 **左→右、上→下**，与列表一致；序号连续（1 2 / 3 4 …），不是左右各一套。
- **每格 40 高、两行**，不做单行硬塞：
  - 第一行：标题（13）；
  - 第二行：艺术家 · 专辑（11，次要色）+ 音源标；
  - 右端 72px 是叠加区：静止是 `时长 + ♡`，悬停换成 `ⓘ / 入队 / ♡` 三个 24px 动作，红心不动。
- 每格：序号 18 + 封面 28 + 文本 + 右端 72；1120 窗口每格约 430，文本约 280。
- **没有列头**；排序只由工具条的 `最近加入 ↓` 表达。双列是「墙」，不是「表」。
- 1120×760：列表 16 行 → 双列约 13 行 × 2 = **26 首**（最后一行半露）。1440×860：约 33 首。
- 单行 32 高的双列能塞 32 首，但标题只剩 150–170，全部截成半句；40 高两行是「多」和「读得懂」之间的取舍，取后者。

不做：两列各自滚动（同一份排序会被拆成两条时间线）、砖石布局、每格多行。

### 4.7 专辑视图与专辑页

- 封面卡上限 128 不变；标题区从 60 收到 44（名称 + 艺术家两行），曲目数移到 tooltip 与专辑页。一屏多出约 1/4 张卡。
- 正在播放的 2px 强调环 + 均衡器角标保留。
- 专辑页页头与新页头对齐：返回、封面、眉标「专辑」、名称、`艺术家 · N 首 · 时长`、播放、入队。

### 4.8 扫描与空态

- 扫描中：页头下一条 2px 进度线（跨页宽），不占布局高度；工具条不出现文字。
- 音源失败：`⋯` 图标上一个小圆点，tooltip 写哪个音源失败；不再常驻一行。
- 空库：保留居中空态与「扫描全部音源」；扫描目录脚注只在空库时出现（现状）。

## 5. 排序

### 5.1 默认：最近加入，倒序

`Song.dateAdded` 已经存在，扫描与合并都保留首次入库时间（`_keepFirstSeen`），只是从没被列表用过。
默认「最近加入倒序」就是读者最常问的那句「我刚加的歌在哪」。

### 5.2 模型

```dart
enum LibrarySortField { addedAt, title, artist, album, duration }

@immutable
class LibrarySort {
  final LibrarySortField field;
  final bool ascending;
  const LibrarySort({
    this.field = LibrarySortField.addedAt,
    this.ascending = false,
  });
}
```

- 归属：`LibraryState.sort`，由 `LibraryController.setSort` 改；**不**进 settings，也不在页面里另存一份。
- 持久化：`LibraryStorage` 增加 `loadSort()` / `saveSort()`，落在 `<支持目录>/library/view.json`。库自己的视图偏好跟库走。
- 排序时机：`_mergeResults` 合并后按当前 `sort` 排一次；`setSort` 再排一次。**不在 build 里排**：20k 首的 `List.sort` 不能挂在每次输入上。
- 搜索与来源筛选保序（`filteredSongsOf` 不动），所以过滤后仍是同一套顺序。
- 文本列用 `compareText`（已有的中文/拉丁比较）；`dateAdded` 与 `duration` 为 0 的条目**无论升降序都排在最后**（未知不是「最旧」）。
- 扫描、合并、增删都走同一个比较器，避免两处规则。

### 5.3 交互

- 工具条 `最近加入 ↓` 打开菜单：最近加入 / 标题 / 艺术家 / 专辑 / 时长。
  （不按音源排序：音源的名字与顺序归 `MusicSourcesController`，库的 domain 不该为了排序去认识它。）
- 点当前字段 = 反向；点别的字段 = 该字段默认方向（文本升序，加入倒序，时长升序）。
- 列头点击等价于同一动作，两处读同一份 `LibrarySort`。
- 专辑视图隐藏排序控件；回到列表时恢复上次选择。

## 6. 状态与数据流

| 状态 | 唯一来源 | 变化 |
| --- | --- | --- |
| 歌曲与顺序 | `LibraryController` / `LibraryState.songs`（已按 `sort` 排好） | 加载、扫描、增删、`setSort` 时重排一次 |
| 排序偏好 | `LibraryState.sort` ↔ `LibraryStorage`（`view.json`） | 启动读一次；改变时写一次 |
| 视图模式（列表 / 双列 / 专辑） | `LibraryPane` 本地 state | 不持久化（与现在一致） |
| 打开的专辑 | `LibraryPane` 本地 state（key） | 不持久化 |
| 悬停 / 聚焦 | 行自己的 state | 只重建那一行 |

页面不新增业务状态；`setSort` 只改 `LibraryState`，不做第二份排序。

## 7. 性能预算

- **行**：去掉事实条（1–4 个 `MetaBadge`，每个约 5 element）后目标 ≤ 150；悬停动作 +3 个 `DenseIconAction` 后仍 ≤ 165。`row_budget_test` 守。
- **排序**：`setSort` 在 controller 里排一次；20k 首预算 ≤ 8ms（新基准 `tool/perf/library_sort_bench_test.dart`）。
- **悬停**：`MouseRegion` / `InkWell.onHover` 只 `setState` 那一行，禁止经过 provider。
- **列头**：静态 `Row`，不订阅播放状态；正在播放只影响行。
- **双列**：`GridView` 每格 element 数与列表行同量级；一屏约 1.6 倍格子，但每个更窄、没有列头与专辑列。
- **滚动**：`itemExtent` 与 `mainAxisExtent` 固定；文字放大时退回自然高度（现状）。

## 8. 可访问性与键盘

- 列头是按钮：`Semantics(button, label: '按加入时间排序，当前降序')`；视觉箭头不参与读屏。
- 悬停才出现的动作，必须由**行聚焦**触发显示；动作在 Tab 顺序里，不隐藏焦点。
- 行本身 Enter = 播放（现状）；空格不抢滚动。
- 颜色对比沿用 `theme_contrast_test.dart`；新增的 11px mono 列头只用 `onSurfaceVariant` 在 `surface` 上的那一对。
- 双列视图的读屏顺序 = 视觉顺序（左→右、上→下），序号连续。

## 9. 落地顺序

### P0 · 骨架（不改数据）

1. 默认窗口 1120×760，高度按工作区 92% 收敛；最小尺寸不变。
2. 页头 / 工具条重排：删眉标、移视图切换、收掉独立刷新与入队图标、统计数字走 mono。
3. `LibraryRowMetrics` 扩成「列头 + 行」共用；列头出现（排序在 P1 接上）。
4. 行去掉事实条、只留一个音源标；行尾 102 叠加区，红心常驻，详情/入队悬停。
5. 专辑卡标题区 60 → 44。

### P1 · 排序

6. `LibrarySort` + `LibraryState.sort` + `setSort` + `view.json`。
7. 默认最近加入倒序；列头与工具条菜单接同一份状态。
8. `dateAdded` 为 0 的归底；`compareText` 与数值比较各一条规则。

### P2 · 宽屏

9. 加入时间列（≥760）与 `formatAdded`。
10. 双列视图（≥860）+ 视图切换第三档 + 回落规则。
11. 宽屏格式 / 码率列（≥1200，可选）。

### P3 · 收尾

12. 扫描进度线 + `⋯` 失败圆点，删掉 `LibraryScanStatusBar`。
13. 空态、专辑页页头对齐、i18n（四种 ARB）、文档与截图基准。
14. `tool/perf/library_sort_bench_test.dart`、`library_sort_test`、`library_row_hover_test`、`library_header_overflow_test`。

## 10. 需要拍板

1. **默认窗口** 900×600 → 1120×760（超出工作区时收 92%）？
2. **双列视图**做第三档（默认列表、记住选择），还是这版先不做？
3. **行内事实**（格式 / 码率 / 无损 / 存储）全部移入详情面板？
4. **红心常驻**、详情与入队悬停出现；还是三个动作都悬停才出现？
5. **`⋯` 菜单**收「重新扫描」与「全部入队」，页头不再有独立刷新 / 入队图标？

## 11. 不在范围

- 分类、分面筛选、左侧分类树——见 [`library-browse.md`](library-browse.md)，与本版同批。
- 侧栏、播放底栏、喜欢页、发现页的视觉。
- 多选、拖拽排序、列宽拖拽、列显示偏好。
- 扫描器与音源适配器的行为。
- 移动端布局。

## 12. 验收

- `flutter analyze` 无 issue；`flutter test` 全绿。
- 900×600 / 1120×760 / 1440×860 × 中文 / 英文 × 100% / 130% 字号：页头、工具条、列头、行都不溢出。
- 默认启动顺序 = 最近加入倒序；重启后保持；点列头可切回标题升序。
- 悬停 / 键盘聚焦时三个动作出现；不悬停时行内只有一个红心。
- 双列在 1120 窗口可用，900 窗口隐藏；缩窗回落列表、放大恢复。
- 一行 element ≤ 165；20k 首排序 ≤ 8ms；滚动基准不高于 D5 的 23ms/步。

## 13. 影响面：哪些页面动，哪些不动

| 页面 | 这批改什么 | 不改什么 |
| --- | --- | --- |
| 音乐库 | 页头、工具条、列头、行尾、排序、默认窗口 | — |
| 专辑页（库内） | 页头对齐；曲目表复用 `LibraryTrackCard`，行改动自动生效 | 不做新布局 |
| 喜欢 | 页头与控件高度对齐 | 仍是双行列表，不换成表格 |
| 队列侧栏 | 不动 | — |
| 发现 | 不动布局 | 页头与控件高度后续对齐 |
| 音源 / 设置 | 不动布局 | 同上 |
| 正在播放 | 不动 | — |

三条边界：

1. **结构性改版只发生在「表格页」这一种页面型**。卡片页（发现）、表单页（音源 / 设置）、详情页（正在播放）不因为音乐库改版而重做。
2. **可共享的只有三样**：`PageHeader`、34 高工具条控件、行尾（`RowTail`）。先放 `shared/ui`，音乐库先用；喜欢页与专辑页在第二批接。
3. **默认窗口是全局的**，但它只是给所有页面多一点空间，不算视觉改版。

如果目标是「每个页面都统一到这套语言」，那要先写一份设计系统（页面型 × 组件），再逐页迁移；不建议在音乐库这一版里顺手改。那是另一个工程，不是这次的一批。
