# 国内音乐方案评估（合法合规前提）

> 状态：快照（2026-11-16） · 适用版本 1.38.1 · 最后核对 2026-11-16

这份文档回答一个问题：在**不碰版权红线**的前提下，Tune 能不能补上「能听的华语歌」，代价是什么。
它记录的是 2026-11-16 这一天对平台政策、判例和同类工具结局的核对结果，**结论可以照抄，但事实会变**——
平台政策与开放能力都可能随时收紧，真要动手前先按第 6 节重新核一遍。

## 1. 结论先行

**合法的华语流行只有一条门：平台官方授权 + 用户自己的账号。** 桌面端（Linux/Windows/macOS）
全行业都没有现成的播放 SDK，所以这条路必须逐案跟平台确认，不能在代码里先假设它存在。

| 路线 | 内容 | 合规性 | 代价 | 建议 |
| --- | --- | --- | --- | --- |
| P0 | 中文电台 + 公版老唱片（零新增版权） | 无风险 | 1–2 天，无账号 | **先做** |
| P1 | 网易云音乐开放平台（用户自己的账号扫码） | 有官方授权通道，桌面端待确认 | 需账号能力 + 平台审核 | 拍板后做 spike（第 6 节） |
| P2 | 官方 ncm-cli 子进程桥接 | 官方口径未确认（issue 未答） | 零审核但不可承诺 | 只做自用开关，不写进文档承诺 |
| — | 逆向接口 / Cookie 注入 / 聚合站内播放 | 红线 | 下架、来函、判赔 | **不做** |

「桌面端待确认」不是保守措辞：网易云开放平台首页的三条产品线是**移动应用 / IOT 设备 / 游戏联运**，
没有桌面；而它的应用签名方式里同时有 **java 签名**（见 [3.1](#31-平台官方授权)），说明非移动端形态并非被排除。
这两件事放在一起，只能得出一个结论：**要问，不能猜**。

## 2. 现状：不是音源少，是品类缺

`需求/音源设计.md` 里的 50 个内置实例，拆开看是五类：

| 类别 | 例子 | 有没有华语流行 |
| --- | --- | --- |
| 开放曲库（CC / 公共领域） | Openverse、Jamendo、ccMixter、Audius、Internet Archive、Wikimedia、LibriVox、PeerTube | 极少（独立音乐、公版老唱片） |
| 试听 | Deezer、iTunes 30 秒 | 有片段，无整曲 |
| 电台 | Radio Browser、SomaFM、Radio Paradise、NTS、Radio France | 中文台有，但**是电台，不是点播** |
| 自建服务器 | Subsonic、Ampache、Jellyfin、Plex、Emby、Funkwhale、Koel 等 | 取决于读者自己有没有 |
| 声明式自定义 | 直链 / M3U / JSON / GraphQL | 取决于读者自己喂什么 |

所以「歌太少」不是适配器不够多，而是**这个品类里没有一家华语流行版权方**。
继续加开放曲库只是在同一个池子里捞鱼，增量必然是「更多小众独立音乐」。

`需求/音源设计.md` §8 已写明不支持任意脚本插件（MusicFree 那套 JS 插件能力已下线），
这条限制在这次评估里反而成了保护：它让「加个 QQ 音乐插件」这种最危险的做法从一开始就不成立。

## 3. 合法路径盘点

### 3.1 平台官方授权

国内四家平台的开放出口，全部按**场景**划分，没有「个人听歌播放器」这一格：

| 平台 | 开放出口 | 准入 | 桌面端可用性 |
| --- | --- | --- | --- |
| 腾讯音乐（TME） | QQ 音乐开发者平台、QPlay Edge SDK | 企业 | **SDK 只标 androidJvm（仅 Android）** |
| 腾讯音乐（公播） | 商家版公播 OpenAPI/SDK | 商家资质 | 唯一的「可公播音源」出口，不是个人场景 |
| 咪咕 | open.migu.cn | 第二步就要审核**公司**资料 + 签约 | 公开案例全是铃声类 |
| 华为 / 小米 / OPPO / vivo | 内容入库、展示数据（MediaControl） | 厂商合作 | 无曲库外放 |
| **网易云音乐** | **开放平台：个人（成年实名）可入驻** | 实名即可，应用仍需审核 | 产品线未列桌面，**待确认** |

真正卡住的不是资质，是 **DRM**：国内流媒体用的是自研加密 + 私用译码协议（腾讯云 AME 文档原话：
「全链加密…客户端需基于专用译码协议播放」），解密实现在移动 SDK 的二进制里。
拿不到 SDK，拿到商务授权也放不出声音。这也是「桌面端没有先例」的根本原因，不是没人想做。

网易云这条路的形状（已核对文档中心，未实测）：

1. 个人实名入驻 → 创建应用 → 生成密钥并上传 → 选一种**应用签名**（java / python / 安卓&ios）。
2. 通过**上线流程**：播放上报测试用例 → 数据验收 → 发布上线。
3. 运行时用户用**自己的网易云账号扫码登录**，拿到该账号的 `accessToken`。
4. 用 `/openapi/music/basic/song/detail/get/v2` 取详情，`withUrl=true` 带播放地址，
   `bitrate` 留空时平台返回「该用户可收听的最大码率」——**权益随账号，不随应用**，这是它合法的关键。
5. `/openapi/music/basic/play/data/record` 回传播放数据，「要求所有接入方必做」。

第 5 条不是可选项：**不回报播放数据，等于绕过平台的结算与统计**，那正是「不正当竞争」认定里最要命的一条。

### 3.2 B2B 曲库转授

真正能卖的「播放使用」授权有三家：DMH 数字音乐（太合）、HIFIVE 音加加、星接 STARLINK（看见音乐）。
共同点：**要企业主体、要商务签约、曲库以独立音乐和代理为主，三大唱片与头部华语热歌不在其中**。
对个人开源项目来说，这条路等于「花一笔钱买一个小众曲库」，不解决「想听周杰伦」的问题。

### 3.3 集体管理（兜不住点播）

- 音著协管**词曲**，网络播放/下载可以许可（公开费率：每上载一首每年 200 元 + 广告收入 5%，费率页 ©2006 无更新）。
- 音集协「互联网」页只引《著作权法》**第 45 条获酬权**（广播/公开播送）。
- 而**交互式点播属第 44 条信息网络传播专有权，必须逐权利人授权**。

一句话：集体管理能覆盖「电台式播送」，覆盖不了「用户点一首歌听」。

### 3.4 公版与开放曲库（合法、免费，但是老内容）

《著作权法》第 44 条：录音制品保护期 50 年，**1976-12-31 之前首次制作的录音已进入公有领域**。
存量比想象中多：

| 来源 | 中文存量 | 备注 |
| --- | --- | --- |
| Internet Archive `language:chinese` | 298 | 戏曲、民乐、老唱片 |
| Internet Archive 标题含 chinese | 4,096 | 含非音乐条目，需再筛 |
| Internet Archive 中文标题/主题 | 1,157 | 质量参差 |
| Great 78 计划中文唱片 | 120–155 | 78 转唱片，公版最干净 |
| Wikimedia Commons | 约 336 | 需 `srnamespace=6` |

一个陷阱：**一条录音有三层权利**（词曲作者：终生 + 50 年；表演者权：50 年；录音制作者权：50 年）。
录音过了 50 年不等于能放——1950 年录的曲子，词曲作者可能 1990 年才去世。老唱片必须逐条核对，不能批量入库。

### 3.5 自助素材授权（个人可买，但不是曲库）

曲线买（TME，个人可实名）、齐音达 / 音速达（酷狗）、100Audio（个人档 ¥257/首，限个人项目）、
火花音悦（个人 VIP ¥299/年，非商用）、曲多多、Vfine（企业 50 万/年量级）。
这些是**给视频配乐**的素材授权，买一首用一首，不构成「可点播的曲库」。

### 3.6 明确放弃的选项

FMA（API 已关停、禁 hotlink）、Pixabay（无音乐 API）、Mixkit / Uppbeat / Bensound（许可不含 App 内点播）、
Spotify Preview（条款明确禁止「用预览构建替代性音乐服务」）、YouTube 音轨（ToS 禁止抽取）、
5sing（用户协议把权利全锁给平台）、豆瓣音乐人（已消亡）、B 站音乐区（robots 禁止）、
KKBOX / iNDIEVOX（无 API）、商用订阅库（Epidemic / Artlist / Musicbed / Soundstripe 全部禁止再分发成点播服务）。

## 4. 风险分级与三条红线

同类工具的真实结局，比任何法律分析都直白：

| 项目 | 结局 | 触发点 |
| --- | --- | --- |
| 洛雪 lx-music-desktop | 2023-10-18 收腾讯音乐函（要求关停），自行下线内置接口，2024-05 转型纯本地播放器 | 链接平台 + 免费提供播放下载 |
| Listen1 | 2017-11-17 收 QQ 音乐 DMCA，仓库临时关闭；2022-09 Firefox 商店下架 | 聚合播放 |
| MyGo | 2026-11-04 收网易云来函要求「立即下线」，archived 并清空 | 「用户自带会员账号」抗辩**未被接受** |
| NeteaseCloudMusicApi | 2024-01-22 收法律通知，01-24 自行删库 | 提供非官方接口 |
| MusicFree / YesPlayMusic / UnblockNeteaseMusic | 仍在 | 壳/源分离，可 24 小时内剥离 |

判例口径：

- (2022)浙01民初570号 / (2023)浙民终1090号（网易云诉科大讯飞「发条」）：**判赔 80 万元**，
  著作权侵权 + 不正当竞争，认定要点是聚合全曲库、复制歌单榜单、代登录账号、**实质替代**。
- (2021)川知民终2116号（咪咕诉淘宝/虾米）：**纯 URL 设链 + 站内 H5 播放也构成不正当竞争**，服务器标准挡不住竞争法。
- (2016)京73民终143号（腾讯诉易联伟达「快看影视」）：确立**服务器标准**，仅设链不侵犯信息网络传播权；
  央视国际诉豆果案更进一步——**跳转官方客户端播放被判不侵权**。
- 无锡影视聚合盗链案：**有期徒刑 5 年 6 个月**。刑事分水岭是「破解技术措施 + 变现 + 规模化」。
- 刑法 217 条现行门槛（法释〔2025〕5号，2025-04-26 施行）：**违法所得 3 万元**即数额较大，非法经营 5 万元入罪。

**三条红线**（写进代码评审也不过分）：

1. **不内置、不分发、不推荐**任何「可播放的音源清单」——包括社区提供的接口地址、Cookie、插件。
2. **不碰技术措施与账号体系**：不破解签名、不代登录、不做账号共享。
3. **不做实质替代**：不整库镜像歌单榜单，并且保留「发函即可 24 小时内剥离」的结构。

「用户自带账号」不构成豁免——MyGo 就是这么写的，然后被要求下线了。区别只在于：
**用户的账号必须是用户自己在官方通道授权的**（扫码、平台下发的 token），而不是应用替他登录。

## 5. 对 Tune 的落地建议

### 5.1 P0：零风险增量（2026-11-16 已实施）

这一档不新增任何版权关系，只是把**已经有能力、但用户不知道**的东西露出来。
落地方式是三个内置实例（`built_in_music_sources.dart`）：

| 实例 | 取法 | 实测规模 |
| --- | --- | --- |
| `chinese_radio` | 开放目录按语言取台（`language=chinese`），只走 Radio Browser | 2,029 个台站 |
| `chinese_78rpm` | Great 78 集合里的中文／粤语那批 | 95 条 |
| `chinese_archive` | 档案里标了中文／粤语／闽南语／国语的音频 | 1,005 条 |

三个都是**同一批目录、更窄的筛选**，没有新增来源，也没有新增合约。

Radio Browser 的中国台站实测 **1,975** 个（抽样 1,000 条中 998 可播），
但按国家筛会漏掉港澳台与新马——所以按语言取台，而不是按国家：
大陆 1,975、香港 66、澳门 20、新加坡 63、马来西亚 76。
这说明「没歌听」里有很大一部分是**发现路径的问题**，不是接入问题。

### 5.2 P1：网易云开放平台（需要拍板，不是纯工程问题）

**先看一个冲突**：`AGENTS.md` §4 明确写着「账号系统不在 v1 桌面主链路内，不要顺手加回来」。
而这条路的前提就是**用户登录自己的网易云账号**。所以这不是「加个适配器」，
而是要决定：**Tune 是否接受「账号」作为一条例外能力**。不接受，P1 直接出局，只剩 P0。

若接受，改动面大致是：

| 面 | 内容 | 备注 |
| --- | --- | --- |
| 新适配器 | `lib/data/services/music_sources/netease_source.dart` | 类比 `jamendo_source.dart`（222 行）量级 |
| 注册 | `built_in_music_sources.dart` 加一个实例 | 同文件 725 行，注意别把默认权重写成 800（它是需要账号的） |
| 登录 | 二维码渲染 + 轮询 + token 落盘 | 新依赖：二维码渲染、安全存储；许可按 `docs/licensing.md` 核 |
| 播放 | `withUrl=true` 取地址，走现有播放链路 | 不缓存、不落盘 |
| 上报 | 播放数据回传 | **必做**，不是可选项 |
| 关下载 | `track_prefetcher.dart:29` 的预取、`SongDownloadService` 的「保存副本」按源停用 | 见下 |

**最容易被忽略的一条**：`lib/features/player/application/track_prefetcher.dart:29` 会对每首远程曲目
（当前曲 + 下一首）抓一份本地副本，`SongDownloadService.isSupported`（`song_download_service.dart:10`）
是**全局平台能力**，没有「按源禁用」的口子。接正版流媒体之前必须先做**按源开关**，
否则这个播放器会一边合法播放、一边把版权音频批量缓存到磁盘——那才是真正致命的证据。

### 5.3 P2：ncm-cli 桥接（只做实验开关）

官方 FAQ 的口径是「个人场景：暂不支持 API，仅可使用 ncm-cli」，而 ncm-cli 官方声明支持
macOS / Linux / Windows。看起来像是给桌面端留的门，但**口径并未确认**：

`NetEase/skills` 的 issue #18（2026-10-19 开，至今 **0 回复**）问的正是这件事——
一个 Windows 桌面产品能不能用**一个产品应用**，通过 ncm-cli 给**多个普通用户**分别扫码授权，
而不需要每个用户自己成为开发者。四个问题里前两个（应用类型、主体资格、个人 CLI 是否仅限本人自用）
直接决定了这条路能不能变成产品功能。

在官方答复之前，它只能是一个**默认关闭的实验开关**，不进设置页的主流程，也不写进 README 的能力列表。

### 5.4 不做清单

- 不做非官方接口（QQ / 网易 / 酷狗的内网接口、第三方镜像 API）。
- 不做 Cookie 注入、不做「粘贴你的 Cookie 就能听」。
- 不做插件市场或「来源订阅」：这不是免责，只是把风险从仓库搬到用户手里。
- 不做 30 秒试听的「拼装播放」：Deezer / iTunes 的预览条款明确禁止用预览构建替代性服务。

## 6. 验证计划

真要做 P1，先花 3 天做个 spike，把不可知的变成已知，再谈排期：

| 天 | 动作 | 产出 |
| --- | --- | --- |
| D1 | 个人实名入驻，跑通 java 或 python 签名的最小请求（搜索 + 详情） | 知道签名难不难、桌面端能不能收请求 |
| D2 | 就「桌面端应用是否受理」向平台问一遍（邮件 / 工单，问题写法和 issue #18 一致） | 知道 P1 是否成立 |
| D3 | 只读打通：二维码登录 → 搜索 → 取播放地址 → 交给现有播放链路 | 单曲能出声，证明适配器可行 |

D2 没有明确答复之前，D3 的代码**不要合进主干**——那会变成一次「先做后批」的既定事实。

## 7. 待核实清单

这份文档里有几处是「读了文档但没实测」的，动手前逐条验一遍：

- 应用签名的具体形式（java / python 两种，算法与密钥分发方式）。
- 二维码登录的接口与 token 有效期、刷新策略。
- 桌面端（Linux 桌面应用，非移动、非硬件）是否被受理为应用类型。
- 播放地址的时效与刷新方式（类比现有 `4.3 播放地址刷新与重试`）。
- 免费账号与会员账号在 `withUrl` 上的差异（`bitrate` 默认值的实际表现）。
