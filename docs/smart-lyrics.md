## 0. 一句话

**核心诉求：有人声乐曲的歌词/字幕，正确率与覆盖率无限接近 1。** 100% 不可达——总有
听不清的演唱、版本有争议的歌词、测不完的抽样——但承诺是硬的：**账本只进不退，
缺口单调收敛**。每多接一个人写源、每换一代模型、读者每打一个标记，账都往 1 靠一格；
99% 只是第一级台阶，每个「9」都是下一级。每个里程碑对着账本汇报，不动的机制换掉。

**读者永远不写词。** 读者的动作只有三个：贴一把钥匙、点一下「补齐曲库」、听到不对的
**打一个标记**（一键，不打字）。标记汇进统一的管理处：系统能复解的自动复解并清标记，
有兴趣的读者可以在那里显式地改——编辑是标记管理的第二动作，不是听歌时的要求。

```text
票池 = 所有能对同一首歌交出词稿的来源
  人写票（共享库，权重最高） + 机器票（每个 ASR 通道一票，≥3 票） + 知识票（LLM 按原曲重建）
共识按行裁决：行行一致整首落盘；个别行分歧 → 只有那几行带「未清标记」
标记回流：读者标记的行/曲重新进票池，票池一变，复解自动清标记，账单调向 1 收敛
```

纯音乐、播客、无人声不是缺口，是**除名**（标「纯音乐」）。能力按工程既有惯例做成
常规 feature（`features/smart_lyrics/` + `data/services/smart_lyrics/`），不引入
插件机制。

## 1. 术语与验收口径

| 词 | 本方案里指什么 |
| --- | --- |
| 覆盖率 | **有人声乐曲**中已解决（无未清标记）的占比；纯音乐与播客不计入分母 |
| 正确 | 一行文本与实际演唱一致（大小写、标点、空格、全半角、繁简差异不算错）；行级时间戳偏差 ≤ 0.5 秒 |
| **验收（99.99% 硬性必须，2026-10-29 换方案二稿）** | **已解决 = 机器证明准入的行集**（§7.6）：文本需 ≥2 独立谱系类一致 + 复核通过，时间轴需双测量差 ≤0.5s，任一存疑弃行；正确率由准入判据结构保证并以留一交叉**无人审计**验证；覆盖率 = 准入率，分歧即缺口 |
| 缺口 | 1 − 覆盖率；本方案管理的唯一数字，只许变小 |
| 收敛律 | 账本只进不退：自动复解不会让账变差；唯一让账回退的是**显式的标记**，且每笔回退都记在标记管理里、有下一动作 |
| 标记 | 对一行/一首词稿的**异议记录**，一键产生、不打字。来源两种：系统（共识未过的分歧行）与读者（「这行不对」「整首不对」「这不是唱的」） |
| 标记管理 | 统一管理所有标记的地方：每一笔标记看得见状态、有去处（复解 / 显式改词 / 撤销 / 除名），没有悬空的标记 |
| 复解 | 标记让曲目重新进票池；新票到场后重新行级共识，分歧行变化则标记自动清 |
| 显式改词 | 标记管理里的第二动作：单行改词的小编辑视图，或整首走外部编辑器 + `manual.lrc`。永远不是默认路径 |
| 票 / 票池 | 一票 = 一份词稿。人写票、机器票、知识票都在池里；池随配置自动变大 |
| 人写票 | 共享库出的人写词稿（含 LRC 时间轴）；本来就正确，权重最高 |
| 机器票 | 一个 ASR 通道一次转写的词稿；先各自纠错再入池 |
| 知识票 | LLM 按标题/歌手从语料知识重建的原曲歌词；只在与机器票 substantially 吻合时作为文本源，时间轴仍取机器票 |
| 共识 | 按**行**投票：时间轴聚类对齐后，逐行取多数。裁决粒度是行，不是首 |
| 除名（纯音乐） | 票池一致判无人声/纯器乐/播客，或读者标「这不是唱的」→ 记「纯音乐」，面板显示说明，不算缺口、不重跑 |
| 基线 | 现状三段取词能拿到的覆盖率——**M0 先量出来再谈台阶** |
| 账本 | 覆盖率唯一记账处：有人声总数 = 已解决 + 有未清标记 + 失败；纯音乐单列；欠的账公开，不藏 |
| 查漏 | 周期性只重问人写票池的低价复查：共享库在涨，去年失败的曲子今年可能有稿 |

## 2. 无限接近 1 的达成路径（承重结构）

五个杠杆按便宜到贵排；每个杠杆对账本的贡献 M0/M3 先量假设、再逐里程碑验证：

| 杠杆 | 是什么 | 为什么站得住 | 预期贡献 |
| --- | --- | --- | --- |
| 一、人写票池做大做先 | LRCLIB 之外接中文生态共享库（M0 评估候选），取词先走人写票 | 人写稿**本来就正确**，零 ASR 成本；中文曲库的人写 LRC 覆盖远高于 LRCLIB 一家 | 合理预期把「已解决」顶到 85–95%（M0/M3 量实） |

**候选源评估结论（2026-10-29 量实后经法务口径复核修正）**：

**接入门槛（一票否决）**：候选源必须是**公开授权的 API**（官方开放平台、正式合作协议）或**知识共享协议**的数据。平台客户端/网页的私有端点一律不碰——无论技术多可达、覆盖多好：用它取数违反平台服务条款（国内已有新浪诉脉脉、大众点评诉百度等判例，未经平台授权抓取其数据服务可被认定为不正当竞争）；且歌词本身的著作权靠平台的授权协议分发，绕过授权体系取词，授权链条是断的。

| 候选 | 授权性质 | 量实/评估 | 结论 |
| --- | --- | --- | --- |
| **LRCLIB**（已接入） | 开放社区库，公开 API，为播放器场景设计 | 中文覆盖偏低（现状基线） | **保留**：合法、免费、可贡献 |
| 读者自带词稿（`manual.lrc`） | 读者自己的文件 | 已支持（文件选择 + 读取链置顶） | **保留**：零授权风险的中文覆盖主路 |
| Musixmatch | 官方 B2B 授权 API（付费、需申请） | 覆盖广（中英皆强） | **合法增量路**：未来若需要中文流行曲覆盖，走其合作 API；成本由方案的「云端预算」机制约束 |
| 网易云 / 酷我 / 酷狗 / QQ 音乐 私有端点 | ❌ 非公开 API；歌词授权链断裂 | 技术探活曾测网易云可达（中文抽 20 命中 10），酷狗/QQ 需签名或登录 | **出局（法务）**：覆盖数字不构成接入理由 |
| Gecimi（歌词狗） | 聚合抓取站 | 已死（空响应） | 出局 |
| Genius | 官方 API 不提供批量离线建库的歌词 | — | 出局（无时间轴 + ToS 不允许此用法） |

人写票池维持 **LRCLIB + 读者自带词稿**；中文流行曲的覆盖缺口由知识票（LLM 重建，合法语料）与读者贡献补，不以违规取数换数字。
| 二、知识票 | LLM 按标题/歌手重建原曲歌词，与机器票对齐互证后才采信文本 | 流行曲库（大头）在 LLM 语料里；等于机器自带一版人写稿；冷门曲自动失效降级，不硬凑 | 热门曲目的机器正确率上限实质抬高 |

**知识票覆盖量实（2026-10-29，真实曲库缺口分层抽 80：中文 40 + 英文 40，推理型端点 mimo-v2.6-flash，app 同款重建提示词，温度 0）**：命中 **zh 0/40、en 1/40**（唯一命中是 Sinatra 标准曲《I've Got You Under My Skin》，18 行），80/80 零调用错误。解读：(a) 本机曲库非流行曲库——中文层大量是播客节目（标题即节目名，约四分之一），英文层是档案/稀有录音，通用模型**如实输出空数组**是正确行为（「不确定不编造」约束生效，空票不入池）；(b) 唯一的著名标准曲命中证明**端到端管道通**——模型认识就答、答就是可用的等行数词稿；(c) 结论：知识票的贡献份额取决于曲库的「主流程度」——典型中文流行曲库上该杠杆成立，本档案库上它诚实归零；播客/说话类曲目不该计入缺口，除名路径是账本诚实的前提。
| 三、查漏长开 | 周期性只重问人写票池（零 ASR 成本、空闲时跑） | 共享库每天在涨、模型在更新；账本因此**单调向 1 收敛**，不是一次性冲刺 | 把「当年无解」变成「迟早有解」 |
| 四、标记零摩擦 | 听到不对的一键标记（不打字）；标记回流票池触发复解 | 打标记的门槛趋近于零，标记量才有规模；复解是机器的事，读者的手势只提供信号 | 兜住机器的错误，喂给前三层消化 |
| 五、时间 | 新共享库、新模型、标记与改稿随时间积累 | 系统设计成「吸收改进不用改代码」：新源进票池、新模型是配置项、改稿落 `manual.lrc` | 查漏与复解让每个改进自动作用到旧账 |

诚实的边界（写在这里，不藏在风险表）：机器票 + 知识票对**冷门曲的演唱识别**有硬上限；
标记是这部分**此刻**的信号，第三、五杠杆是它的**长期解**——共享库在涨、模型在换代，
今天被标记的曲子明年可能被新票源白拿。方案承诺的不是某个静态百分比，而是：
**账本单调收敛、每一个「9」都有明确的杠杆在推、可验证的精度不超过抽样预算允许的
范围（见 §10）。**

## 3. 结论与默认决策

| 决策 | 默认 | 理由 |
| --- | --- | --- |
| 验收 | 双数字按九的台阶爬（99% 起），每里程碑汇报；账本遵守收敛律 | 核心诉求是无限接近 1；不动的机制换掉 |
| **读者的角色** | **只打标记，不写词**：面板上一键标记；编辑只活在标记管理里，是显式的第二动作 | 让用户改词复杂度高、易出错；打标记门槛为零，信号量反而更大 |
| 引擎升级重查 | 读者新增票源/换模型后，一键「用新票源重查失败曲目」（显式动作，不自动重跑 ASR） | 时间杠杆的入口：新引擎进来，旧死账复活 |
| 形态 | 常规 feature：`features/smart_lyrics/` + `data/services/smart_lyrics/`，与 `features/discovery` 同款 | 运行时热插拔不可行，同仓「插件」只剩间接层的成本；隔离由既有分层规矩保证 |
| 任务账本存储 | `library.db` 新表 `smart_lyrics_tasks`，由 feature 自己的 `SmartLyricsTaskStore` 拥有 | 与 `listening_signals` 同一先例：feature 拥有 store，表在库里 |
| 分母校正 | 票池一致判无人声，或读者标「这不是唱的」→ 除名；播客内容排除 | 纯音乐永远不会有词，留着它台阶是假数字 |
| 票池 | **≥3 票才许自动落盘**：人写票每源一票 + 每个 ASR 通道一票 + 知识票一票 | 两票会一起错（同源相关误差），异构多票才够；票池随配置自动长大，不加配置项 |
| 共识粒度 | **按行不按首**：行行一致整首落盘；分歧只标记行 | 复销量从「每首」降到「几行」，是降低使用复杂度的最大一刀 |
| 标记管理 | **统一一处**：标记（系统+读者）全在这里看状态、给出路（复解/改词/撤销/除名） | 标记不能打了就没；有去处的标记才是收敛的燃料 |
| 配置形态 | **贴一把钥匙**：服务商预设模板（预填地址与模型名），高级项折叠 | 配置项越少越敢开批量；模板消灭「模型名该填什么」 |
| 本地引擎 | **app 自管下载**：二进制 + 模型一个按钮下齐（含校验和）；系统已装的直接用 | 不要求读者装系统软件；解码评估 media_kit/libmpv 管线，系统 ffmpeg 只当退路 |
| 纠错 | 机器票落池前必过一道 LLM 纠错（带标题/歌手/专辑提示） | 中文同音字、英文连读切词是 ASR 主要错型；纠错在投票前做，免得票间传染 |
| 引擎形态 | 云端（OpenAI 兼容）先行；本地 whisper.cpp 随后，是免费票与异构第二票的主力 | 全走云端是真金白银；本地票把批量成本降为零（换时间） |
| 查漏 | 默认开：只重问人写票池，空闲时跑，零 ASR 成本；**被标记的曲目优先** | 账本单调向 1 收敛；重跑 ASR 不默认 |
| 产物落盘 | `<歌名>.smart.lrc`；翻译/音译进 `<歌名>.smart.json`；显式改词落 `<歌名>.manual.lrc` | 机器稿与匹配稿分开，读者能辨、能重生成、能顶掉 |
| 读取顺序 | `manual.lrc` > `.lrc` > `.smart.lrc` | 读者的词永远赢，app 匹配到的次之，机器生成垫底 |
| 密钥与端点 | 读者自配，存本地偏好（键 `smart_lyrics`）；应用不内置密钥 | 与音源凭据同一待遇；预设模板只预填地址与模型名，不预填钥匙 |
| 隐私边界 | 云端通道把音频上传到读者配置的端点；本地票零外发 | 批量下是持续外发，设置页写明，开跑前确认一次 |
| 逐字卡拉OK | 不做 | [lyrics.md](lyrics.md) §3.1 已定；ASR 词级时间戳够行级 LRC 用 |
| 纯文本对齐 | 不做 | 强制对齐工具链重，云端转写接口不支持；降级路径是「ASR 重转再校对」 |

## 4. 目标与非目标

### 4.1 目标

1. **无限接近 1**：覆盖率与正确率按九的台阶爬（99% 是第一级），账本遵守收敛律
   （只进不退、无悬空标记）。这是唯一验收，其余目标都是它的支撑。
2. **读者只有三个动作，一个都不写字**：贴钥匙（一次）、点「补齐曲库」（一次）、
   听到不对的打个标记（一键）。其余全部自动：挑票、对齐、共识、纠错、落盘、重试、
   续跑、查漏、复解清标记。
3. **账本可见**：设置卡显示有人声总数与三笔账（已解决 / 有未清标记 / 失败），
   纯音乐单列，不进分母。
4. **标记有去处**：每一笔标记在标记管理里看得见状态；复解成功自动清，改词与撤销
   是显式动作，没有打了就没的标记。
5. 单曲闭环：点「智能生成」或批量跑到它，共识稿几分钟内可唱；下次直接读本地
   `.smart.lrc`。
6. 失败各有去处：没贴钥匙 → 置灰指设置；取音频失败/上传失败/识别为空 →
   各自文案与重试；批量单首失败不挡后面。
7. 900×600 / 760×520 不溢出，文案四语同步。

### 4.2 非目标

- 不做插件机制（端口、挂载点、运行时加载）；隔离靠既有 feature 分层。
- **不在歌词面板里做任何写词的入口**；不做「打开面板就被要求校对」的流程。
- 不做校对之外的通用歌词编辑器；显式改词只改文本，不增删行。
- 不做「默认全自动全库跑」：批量必须读者点过「补齐」且预算没花完（查漏除外，
  它只重问人写票，零成本）。
- 不做逐字卡拉OK、纯文本强制对齐。
- 不做应用内置密钥、代理配额、账号体系。
- 不改取词三段的语义与顺序（[lyrics.md](lyrics.md) §3.2 不动）。
- 不新增第二份歌词状态：歌词的事实来源仍是 `LyricsController`。

## 5. 现状与约束

### 5.1 现有链路（本方案接管末端的空缺）

```text
LyricsController._lyricsFor(song)
  1. 曲目旁的文件（manual > lrc）
  2. MusicSourceService.fetchLyrics：标签自带 → 音源自带 → LRCLIB
  ── 三段全空 → 面板「这首歌没有歌词」────────── 单曲入口从这条缝进来
```

- 竞态、会话记忆（`LyricsMemory`）、`_generation` 丢弃旧答案的机制现成可用。
- 人写票池在现有取词语义之外**只增不改**：新增的共享库作为票源进
  `data/services/music_sources/`（`LyricsProvider` 的更多实现），不碰三段顺序。

### 5.2 硬约束怎么守

| 约束 | 本方案的落法 |
| --- | --- |
| 跨 feature 不碰 presentation | `features/smart_lyrics` 只 import player 的 application/domain；面板上的标记动作由 player 侧的挂点回调 |
| service 不依赖 Riverpod、不 import `features/` | `SmartLyricsService` 放 `data/services/smart_lyrics/`，只编排 I/O，状态归 controller |
| 状态只有一个主人 | 生成/批量的**结果**经 `LyricsController` 进 `LyricsState`；不持有第二份歌词状态，`SmartLyricsController` 只持有进度；标记归 `SmartLyricsTaskStore` |
| UI 线程不做同步 I/O / 重活 | 云端走 dio 异步；本地引擎是子进程；共识对齐在 isolate；批量 worker 全程后台，一次一首 |
| 每操作不做写放大 | 单曲成功写一个 `.smart.lrc` + 任务表一行状态更新；标记是任务表一行更新，不碰词稿文件 |
| 库不入内存 | 批量队列、账本与标记存 SQLite（`smart_lyrics_tasks` / `smart_lyrics_marks` 表），按需取，统计在数据库里算 |

## 6. 技术路线评估

### 6.1 云端：OpenAI 兼容接口（先行）

| | |
| --- | --- |
| 转写 | `POST {baseUrl}/audio/transcriptions`，`response_format=verbose_json` → 带起止时间与置信信号的 segments；**同一个钥匙配多个模型名 = 多张机器票** |
| 纠错/知识票/翻译/音译 | `POST {baseUrl}/chat/completions`，逐行输入、要求等行数 JSON 输出 |
| 依赖 | 零新原生依赖（dio 现成） |
| 成本量级 | 一票约 $0.003–0.024/首（便宜聚合端点比官方低近一个量级）；4000 首、缺口 30%、三张机器票 ≈ **$10–90 一次性**，开跑前按读者自己的端点给预估 |
| 隐私 | 每首 3–8 MB 上传到读者配置的端点；批量时持续外发 |
| 风险 | 各家端点对 verbose_json 支持参差 → 宽容解析，缺 timestamps 的票降级为「无时间轴参考票」，不参与时间共识 |

### 6.2 本地：whisper.cpp（app 自管下载）

| | |
| --- | --- |
| 形态 | 二进制 + ggml 模型（tiny/base/small 75–466 MB）由 app 下载到应用支持目录，含校验和；**系统已装 `whisper-cli` 则直接用，下载只是兜底**；不进 FFI，进程边界隔离崩溃 |
| 解码 | **M4 评估结论（2026-10-28）：不引入 ffmpeg。** media_kit/libmpv 只是播放器管线，没有落 PCM/转码的公开 API，不可用于解码落盘；捆绑精简 ffmpeg 有体积与许可成本，违背「无新增依赖」。新版 `whisper-cli` 自带 dr_wav/dr_mp3/dr_flac/stb_vorbis，直接吃 flac/mp3/ogg/wav——**音频原样喂进去，不落中间 WAV**。旧版系统二进制（只认 WAV）会在该通道失败，票池照常缺这一票投票，日志提示读者把二进制换新或手动放置新版 |
| 速度 | CPU 上 4 分钟歌约 0.5–3 分钟（tiny→base）；批量 2000 首是「过夜」量级，GPU 快一个量级 |
| 隐私 | 零外发；引擎与模型下载（含校验和）是唯一一次网络行为 |
| M4 已落地 | `WhisperLocalEngine`（子进程转写，`requestCancel` 可中途杀掉，产物只在干净退出后读、成败都清理）+ `WhisperAssets`（系统 PATH 优先、可执行位判定、app 目录兜底）+ `WhisperModelStore`（从 whisper.cpp 官方模型仓下载，sha256 对照官方 tree API 的 LFS 清单，不符即销毁）；设置卡「本地引擎」下拉选模型 + 「下载模型」按钮，`local:<模型名>` 作为一张永远免费的机器票进池 |
| 结论 | **免费票**与异构第二票：一个按钮装好，装了就永远有一票不花钱 |

### 6.3 票池与共识（核心算法）

- **票源**：人写票（LRCLIB + M0 评估新增的共享库，每源一票）+ 机器票（每个 ASR
  通道一票：云端可配多个模型名，本地引擎装了就是一票）+ 知识票（LLM 重建）。
  默认要求 ≥3 票才许自动落盘；不足 3 票的曲子出「未清标记」而不落盘。
- **异构性**：票源尽量不同家族（whisper 系 + 本地小模型 + 人写源 + LLM 知识），
  相关误差才不会整池一起错；同端点同模型的重复票不额外计票。
- **对齐**：按行时间轴聚类（起始差 ≤1 秒并作同一行），对齐在 isolate 里算。
- **投票**：逐行取多数；人写票权重压机器票（1 张人写票顶 2 张机器票）；知识票只在
  与机器票 substantial 吻合时采信文本（时间轴始终取机器票）；平票取时间戳更细的票，
  再平取先到。
- **纠错在前**：机器票先各自过 LLM 纠错再入池，免得同音字错误在票间传染。
- **产物**：行行一致 → 整首 LRC 落盘；有分歧行 → 一致的行照常落盘，分歧行记为
  系统标记（存任务表，面板据此标记）。

### 6.4 分工

- 单曲生成：人写票先试（便宜且对），不够票再跑机器票与知识票。
- 批量补齐：本地票优先跑（零成本预热），云端票按预算补。
- 纠错/知识票/翻译/音译：走文本模型，与云端共用同一份兼容配置。

## 7. 方案

### 7.1 单曲生成闭环

```text
点「智能生成」
  → 取音频：本地用文件；在线曲目有副本用副本，否则 dio 拉流到临时文件
  → 凑票：人写票池全部试一遍 → 凑够且一致 → 直接落盘收工（很多曲子到这就完了）
    不够票 → 机器票逐通道跑（可取消），每票先各自纠错；知识票并行重建
  → 共识：行级投票 → 无人声？→ 标「纯音乐」收工
       行行一致 → 拼成 LRC → saveSmartLyrics → LyricsController 重建生效
       有分歧行 → 一致部分落盘，分歧行记系统标记（待复解）
```

- 失败各回各态：没贴钥匙（置灰 + tooltip 指设置）、取音频失败、上传失败、识别为空。
  文案进 l10n，错误只记日志不打断播放。

### 7.2 批量补齐与查漏（向 1 收敛的主力）

- **任务表** `smart_lyrics_tasks`：曲目 id、状态
  （`pending / running / done / disputed / instrumental / failed / skipped`）、
  票数与分歧行数、尝试次数、最后错误、时间戳。取词三段能拿到的曲子不入队。
- **标记表** `smart_lyrics_marks`：曲目 id、行号或整曲、来源（系统/读者）、
  状态（未清 / 已复解 / 已改词 / 已撤销）、时间戳。
- **优先级**：被标记的曲目最优先 > 最近播放 > 喜欢 > 其余（按添加时间）；
  同优先级按曲目 id 稳定排序，中断重跑顺序不跳。
- **默认参数开箱即用**：同时一首、曲目间隔 2 秒、本地票优先、云端票预算默认上限
  （设置卡可改，高级项里）。
- **预算**：云端票开跑前按读者自己的端点给预估，达到上限自动暂停并报告。
- **查漏（默认开）**：空闲时周期性只重问人写票池（「失败」「disputed」「有未清标记」
  中的可复解者），零 ASR 成本；有新稿就走正常共识，复解成功自动清标记。
- **重查**：读者新增票源或更换模型后，批量卡多一个「用新票源重查失败曲目」动作——
  只对失败账与未清标记跑，新引擎带来的每一票都可能复活死账。
- **断点续跑**：重启从 pending 继续；扫描发现新无词曲目不自动入队，设置卡显示
  「新增 N 首待补」。
- **进度**：设置卡显示账本三笔账 + 失败数；失败单首可看原因并重试。

### 7.3 读取顺序与「重新查找」的语义

```text
manual.lrc > .lrc > .smart.lrc
```

- 面板显示的词若来自 `.smart.lrc`，动作行多一条「重新查找」：强制走网络取词，
  取到就写 `<歌名>.lrc` 并把它顶上去。机器稿**永远垫底**，但不挡后来补上的真词。
- `.smart.lrc` 头部写注释行（解析器不显示）：票数、票源构成、未清标记位置、日期。
- 缺 timestamps 的票降级为参考票；整首无时间轴的稿退纯文本展示，仍计入覆盖（口径见 §1）。

### 7.4 标记与标记管理（读者的角色全在这里）

**打标记（一键，不打字）：**

- 歌词面板每行行尾一面小旗（悬停/长按显现），点一下 = 「这行不对」，再点 = 撤销。
- 动作行上两个整曲标记：「整首不对」「这不是唱的」。
- 面板**没有任何写字的入口**；被标记的行照常高亮滚动，样式带一面小旗以示有未清标记。

**标记管理（统一一处，`features/smart_lyrics` 的页面）：**

- 列出所有标记：曲目、行/整曲、来源（系统/读者）、状态、时间；按曲目分组、
  未清的排前。
- 每笔标记的出路：
  - **等复解**（默认）：标记让曲目重新进票池，查漏与重查会带上它；复解成功自动清，
    面板当场换词；
  - **显式改词**（有兴趣再来）：单行改词的小编辑视图，存 `manual.lrc` 并清标记；
    整曲想大改的，走外部编辑器 + 「选择歌词文件」，同样是清标记的一条路；
  - **撤销标记**：我标错了；
  - **标纯音乐**：「这不是唱的」一键除名。
- 标记管理从两处可达：设置卡的「智能歌词」卡、歌词面板动作行的「标记」入口。

**为什么这样分**：打标记是听歌时的顺手事（一键），改词是坐下来做的事（显式）；
两者分开，面板保持纯展示，读者的词永远只从 `manual.lrc` 来。

### 7.5 增强（翻译 / 音译）

- 入口在有词态：「翻译」「音译」，各只做一次，做完变「已对照」。
- 逐行输入，要求**等行数** JSON 输出；行数对不上按失败处理（不硬凑）。
- 渲染：对照行以次级样式贴在原文行下，不参与定位、不高亮、不进 `indexAt`。
- 落盘 `<歌名>.smart.json`（以时间戳为键）；`.smart.lrc` 重新生成时旧对照作废。

### 7.6 机器证明准入（99.99% 结构保证，二稿 2026-10-29：无人审）

**原则**：不把每行做到 99.99%，只把**机器能交叉证明的行放进已解决**——正确率是准入判据的推论，存疑即弃、宁缺勿错，全程无人核对。

- **文本行准入**（全部成立才放行）：≥2 个**独立谱系类**归一化后全等（同类多源只算一类，防同源同错）——A 人写共享库类 · B 两个不同家族 LLM 独立重建一致 · C 两个不同家族 ASR+纠错独立稿一致；外加独立家族复核 LLM 复读「行文 vs 上下文」通过。任一存疑 → 弃行（是弃不是修），该行仍是缺口。
- **时间轴行准入**（双独立测量交叉）：ASR 段边界与强制对齐（词级时间戳锚定已定文本）各出一值，两值差 ≤0.5s 才放行；>0.5s 弃行。**M11a 已实现前者对**：准入各类的代表时刻互为独立测量（如人写类时刻 vs ASR 类时刻），类间差 >0.5s 弃行；无真实时刻的类（LLM 重建）不参与计时——强制对齐作为第三测量待 M11b。
- **审计接线与平票规则（已实现）**：留一审计随每次落盘自动运行，`checked`/`mismatched` 与三除N上界随 outcome 带出并记日志；轮换中支持度**平票**的异文不算矛盾（只是存疑跳过），只有支持度严格更强的异文才是抓到——审计只审「剔除任一声仍能自立」的冗余行。
- **多家族知识票（M11c 已实现）**：`chatModel` 支持逗号分隔多个模型名——每个模型一票 `knowledge:<模型>`，两个**不同家族**的重建一致才让知识类发声；纠错仍走第一个模型；单名配置行为不变。强制对齐（第三时间测量）待接。
- **无人审计（M11b 已实现）**：留一交叉——四个以上独立声音（跨两类）共同承载的行进入轮换审判：逐一剔除一个家族重跑准入，仍须判出同一文本；判出异文即「抓到」，判不出话的轮换跳过不计。`checked`/`mismatched` 给出漏网率估计，零抓时按三除以 N 给置信上界——机器校机器，全程无耳。三声以内（含 A+2C 的三声形态）在双类判据下轮换必剩单类，不可核验，如实不计入审计。
- **无人审计**：正确率测量也全自动——放行集上留一交叉（第 K 个不参与准入的方法作裁判），量出漏网率与置信区间；机器校机器，可复现、无耳。
- **覆盖率语义**：覆盖率 = 准入率；分歧即缺口。冷门曲自然不放行（诚实缺口），新源/新模型随时复活（查漏长开沿用）。漏网是「跨独立谱系联合同错」的乘积事件（~ε²~ε³ 量级），99.99% 靠判据不靠希望。
- **现实门槛（诚实）**：判据要求 ≥2 家族 ASR 模型名 + ≥2 家族文本模型 + 合法人写源；单通道（如本机仅有 tiny）准入为 0、覆盖为 0，如实显示不硬写。云端预算上限机制沿用。
- **资产映射**：票池/共识/批量/查漏/健康度/标记全部保留，角色从「直接落盘的依据」变为「准入判据的输入与缺口复活器」；分歧行、等行数、收敛律规则原样生效并成为准入判据的一部分。


## 8. 隐私与成本

- 云端通道上传**整首歌的音频**到读者自己填的端点；批量是持续外发，设置卡说明
  原文写明，开跑前再确认一次。知识票只发文本（标题/歌手/草稿行），不发音频。
- 本地票零外发；引擎与模型下载（含校验和）是唯一一次网络行为。
- 应用自身不收集识别内容、不遥测；错误日志只记异常与长度，不记音频与歌词正文。
- 成本由读者与服务商结算；批量给**预估与上限**，不替读者记账。

## 10. 测试策略与度量

| 目标 | 场景 |
| --- | --- |
| 票池共识 | 对齐聚类容差；人写票权重压机器票；知识票只在吻合时采信文本、时间轴恒取机器票；平票取时间戳更细；同端点同模型不重复计票；<3 票不自动落盘；对齐在 isolate 不卡测试 |
| 纠错 | 提示词带标题/歌手；输出行数必须等于输入；纠错稿仍过 `LyricsDocument.parse` |
| 引擎接口 | fake 引擎回答 `TranscriptionResult`；翻译/音译行数不齐按失败处理；`dispose` 后再调要抛 |
| Service | 本地曲目不下载直接转写；在线曲目先找本地副本；缺 timestamps 的票降级参考票 |
| 人写票 | 新共享库实现只进票池不改三段取词；来源失败不挡其他票 |
| 标记 | 面板一键标记/撤销不写字；标记进标记管理有状态有去处；复解成功自动清且面板换词；显式改词落 `manual.lrc` 并清标记；改词只改文本不增删行；「这不是唱的」除名；被标记曲目在批量与查漏中最优先 |
| 查漏与重查 | 查漏只重问人写票池、空闲时跑、新稿走正常共识；重查只对失败账与未清标记、不自动触发 |
| 读取顺序 | manual > lrc > smart；只有 smart 时离线可读；「重新查找」命中真词后 smart 被顶下 |
| 单曲闭环 | 成功写 `.smart.lrc` 且面板立刻换词；切歌后旧进度被丢；取消不留半截文件 |
| 批量 | 入队的全是三段落空的曲目；优先级稳定（标记最优先）；预算到顶自动暂停；中断重跑不跳号不重跑 done；单首失败不挡后面；间隔生效 |
| 账本 | 三笔账 + 纯音乐计数与任务表/标记表实际状态一致；扫描新增不自动入队；已解决不回退（收敛律） |
| 设置 | 预设模板往返；密钥改动即时生效；未贴钥匙时按钮置灰；高级项折叠不丢配置 |
| 增强 | 对照行不高亮、不参与定位；落盘后重启仍在；词重生成后旧对照作废 |
| 门禁 | `flutter analyze` 无 issue、`flutter test` 全绿、文案四语 + `flutter gen-l10n` 产物入库 |

**双数字度量（M3 起，每个里程碑后汇报，按九的台阶爬）**：

- **覆盖率**：账本实数——已解决（无未清标记）/ 有人声总数；缺口只许变小（收敛律）。
- **正确率**：分层抽样（直录棚歌 / Live / 说唱 / 非中文各一层），按 §1「正确」定义
  人工判。**每个「9」的验证成本约 ×10**（99% 每层 ≥200 首、99.9% 约 ≥4000、
  99.99% 约 ≥40000）——抽样预算按当前台阶配，配不起的台阶如实写「未验证到此
  精度」，不拿小样本冒充大数；账本上无未清标记是高台阶处更硬的口径。
  分层判定按「Live > 说唱 > 非中文 > 直录棚」的固定优先级归入一层（重叠不重复
  计），判定依据：标题/专辑含 live/现场 → Live；genre 含独立词 rap/hip-hop/说唱/
  嘻哈 → 说唱；语言标签非 zh 或标题无中文字符 → 非中文；其余 → 直录棚。
  抽样是种子确定性函数（种子 + uri 的稳定哈希），同库重抽同集、只增不减，核对
  轮次可续跑；改判以最后一笔为准。
- **两个数任一停滞，对应机制按 §2 的杠杆顺序加码或更换，方案文档随之修订。**

**99.99% 是目标台阶，不是保证值（2026-10-29 钉死口径）**：

- **保证了的**（机制级，有测试或真机背书）：账本只进不退（收敛律）；分歧行宁空不写错（真机验证）；等行数硬约束——纠错/翻译/音译/知识票对不上行数即失败不硬凑；知识票须 LCS 对齐 ≥60% 才采信文本；人写票权重顶机器票；复解成功自动清标记、无悬空标记；通道健康度机制淘汰连败通道；抽样确定性可复现。
- **不保证的**：数字本身——到达 99.99% 需要每层 ≥4 万样本的**人耳核对**（验证成本而非机制成本，配不起就如实写「未验证到此精度」）；读者曲库的票池供给——落盘需 ≥3 票，本机恰好三源（LRCLIB + 本地 + 知识票），任一缺席则缺口冻结而非强写；机器票的基座质量——tiny 在真实 1958 录音上行级约 75%，台阶靠换更好的通道与标记复解往上顶，不靠底座奇迹。
- **一句话**：方案卖的是「每一步都可验证、每个数字都有出处、错了有去处」的收敛过程，不是终点数字的彩票。99.99% 在机制上**可达**（异构票池 + 标记复解 + 查漏长开 + 换代模型皆为已实现的杠杆），在当下**未验证**——两个词不能混。

## 11. 风险与回退

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 人写票池覆盖不够（共享库没有的曲子） | 杠杆一贡献低于预期 | 只接公开授权的源（门槛见杠杆一表）；缺口由知识票补热门曲 + 查漏等共享库长大 + 读者自带词稿；不以违规取数换覆盖 |
| 票源同源一起错（多个 whisper 系模型在相同处栽） | 共识给出假信心 | 异构凑票（人写源 + 云端多家族 + 本地小模型 + LLM 知识票）；人写票权重压阵；M3 抽样按层量真实正确率 |
| 知识票「幻觉重写」（LLM 编歌词） | 错词混进共识 | 只在 substantial 吻合时采信文本；时间轴恒取机器票；分歧行不落盘 |
| 冷门曲的演唱识别有硬上限（哼唱、说唱、强混响） | 这些曲子长期带标记 | 此刻由标记信号兜着；长期由杠杆五解——查漏与「新票源重查」让死账复活，份额单调收缩 |
| 标记打了没人管，悬在那里 | 读者觉得标记没用 | 标记管理的状态与出路是硬约束（§7.4）：每笔标记可见、可等复解/改词/撤销；复解自动清 |
| 误标（读者听错、系统误判） | 好稿被冤枉 | 标记可撤销；复解只在有新票时才动稿，没新票不改一个字 |
| 三张机器票的费用 | 云端账单 | 人写票先行（多数曲子到这就完）；本地票零成本；云端预算上限 + 预估 + 默认不自动 |
| 无人声误判 | 账本失真 | 票池一致才除名（保守）；读者可改判；`instrumental` 可重置重测 |
| 各家端点兼容参差 | 拿不到时间轴/置信 | 宽容解析；缺 timestamps 降级参考票；本地票是完全可控的兜底 |
| 本地引擎自管下载的分发源不稳 | M4 拖期 | 系统已装的 `whisper-cli` 直接用；下载失败退回提示手动放置；不阻塞 M0–M3 |
| 批量拖慢前台 | 卡顿、播放受影响 | 同时一首、曲目间隔、全在后台；播放中的曲目不取它的音频 |
| 识别结果遮挡未来补上的真词 | 错词常驻 | smart 永远垫底 + 「重新查找」顶掉 + 头部注释声明来源 |
| 密钥明文落盘 | 本机泄露面 | 与音源凭据同一现状同一待遇，文档写明 |

**回退**：M0（统计）、M2（票池与单曲）、M4（本地）、M5（批量与查漏）、M6（标记）、
M7（增强）各自独立成提交；任何一层不满意单独回退，不影响取词三段与现有面板状态机。

## 12. 实施计划

1. **M0 基线量测**：覆盖率与缺口统计（有词/无词/来源分布），设置卡显示账本雏形；
   评估人写共享库候选清单并量各源覆盖——**杠杆一是收敛的主承重，它的贡献先量实**。
2. **M1 接口与票池**：`SmartLyricsEngine` / `SharedLyricsSource` 接口 + 票池纯逻辑
   （对齐、投票、分歧行、知识票采信，isolate 可跑）+ 设置卡预设模板（贴钥匙）+
   「智能生成」置灰态。
3. **M2 单曲闭环**：凑票 → 纠错 → 共识 → LRC → `.smart.lrc` → 面板生效，
   含分歧行系统标记与「重新查找」顶掉语义。
4. **M3 抽样正确率**：分层抽样集（第一台阶每层 ≥200 首）与人工核对记录表；此后每个
   里程碑汇报双数字与当前台阶——账本对着这两个数爬九。
5. **M4 本地引擎**：app 自管下载（二进制 + 模型）、解码管线评估、可取消子进程转写；
   结论写回 §6.2。
6. **M5 批量与查漏**：任务表、优先级（标记最优先）、预算、断点续跑、账本界面、
   查漏长开、重查入口。
7. **M6 标记与标记管理**：面板一键标记（行/整曲/纯音乐）、标记管理页（状态与四条
   出路）、显式改词的小编辑视图。
8. **M7 增强**：翻译 + 音译，双语渲染，`.smart.json` 落盘。
9. **M8 收尾**：四语文案 + `gen-l10n`、architecture.md / lyrics.md / AGENTS.md
   文档同步、门禁全绿。

每个里程碑按 TDD 走：先写会失败的测试，再写刚好能过的实现。
