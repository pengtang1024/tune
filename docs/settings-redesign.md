# 设置页重构（设计提案 v1）

> 2026-10-31。回答「设置页怎么从一张长表变成紧凑、好看、好用的控制台」。
> 相关：[conventions.md](conventions.md)（尺寸/字体）、[architecture.md](architecture.md)（状态归属）、
> [i18n.md](i18n.md)（文案）、[library-browse.md](library-browse.md)（刚落地的新页面语言）。
> 状态：**已实施**（2026-10-31）。

## 1. 现状

设置页是一张 720 宽的单列长表：

- 9 张卡（外观 / 音乐库 / 播放 / 发现 / 音源健康 / 智能歌词 / 桌面 / 关于 / 更新），卡内 20 内边距、卡间 14；
- 每张卡都有编号 + 眉标 + 标题 + 描述 + 内容，信息层级重复；
- 播放、歌词、发现全是**逐项开关/输入**，读者要自己拼出一套行为；
- 1120 窗口右侧约 400px 空着，却仍把所有内容竖着排；
- 智能歌词卡尤其长，配置项与日常开关混在一起。

问题不是「哪一颗开关丑」，是**没有快捷路径**：大多数读者只想要一套「队列优先 / 省电 / 本地优先」的行为，却被迫逐项理解每个字段。

## 2. 目标

1. **紧凑**：默认 1120×760 下，一屏能看到一个分区的全部内容；不再是一张几屏长的表。
2. **好看**：沿用音乐库的「唱片目录」语言——少编号、少眉标、预设卡有封面感；控件同高同圆角。
3. **好用**：每个分区先给 2–4 个**预设**，点一下就把一组字段设好；「自定义」是附加按钮，打开才看到逐项开关。
4. **可找回**：自定义值不会被预设吞掉；当前值不属于任何预设时，显示「自定义」选中。
5. **可扩展**：加一个设置项时，先想它属于哪个预设；没有预设可归的才进自定义 sheet。

### 2.4 已拍板（2026-10-31）

| 决策 | 选择 |
| --- | --- |
| 布局 | **两者结合**：左侧分区导航 + 「全部」总览页 |
| 首版预设 | **六个分区全做**：外观 / 音乐库 / 播放 / 歌词 / 发现 / 桌面 |
| 自定义 | **每个分区一个「自定义…」sheet**，逐项开关留在 sheet 里 |
| 搜索与重置 | **都做**：顶部搜索 + `⋯` 恢复本分区/全部默认 |

## 3. 方案

### 方案 A：左侧分区导航 + 右侧预设（推荐）

- 设置页变成两栏：左 176 宽的分区导航（外观 / 音乐库 / 播放 / 歌词 / 桌面 / 关于），右侧只显示当前分区。
- 每个分区顶部是 2–4 张预设卡（图标 + 名称 + 一句解释 + 选中环），下面是「自定义」按钮与少量快捷动作。
- **优点**：一屏一个主题，最紧凑；分区可加搜索；预设是主角，逐项开关退到 sheet。
- **缺点**：多一层导航；分区切换要维护本地状态/路由。
- **适用**：桌面设置项多、读者目标明确的场景。

### 方案 B：仪表盘网格 + 预设

- 不分分区，所有卡排成两列（1120 下每列约 440），预设卡内嵌。
- **优点**：所有东西一眼可见；实现比导航简单。
- **缺点**：卡多时仍要滚很长；两列宽度下长文案/输入框会挤；「紧凑」只做到一半。
- **适用**：设置项少、希望全览的产品。

### 方案 C：预设向导

- 首次进入走一遍「你主要怎么听歌」的向导，之后只显示预设。
- **优点**：最省心。
- **缺点**：设置不是一次性行为；改一个开关要重走向导；不推荐。

## 4. 推荐：方案 A

### 4.1 信息架构

```text
设置
├─ 全部      六张分区卡的总览（当前预设 + 一句状态）
├─ 外观      主题预设（跟随系统 / 浅色 / 深色）+ 语言
├─ 音乐库    自动扫描预设 + 文件夹 / 缓存 / 立即扫描
├─ 播放      队列优先 / 单曲优先 / 收藏优先 + 自定义
├─ 歌词      手动 / 平衡 / 本地双家族 + 自定义（API、模型、预算）
├─ 桌面      托盘常驻 / 关闭即退出 + 媒体控制 + 默认播放器
└─ 关于      版本 / 许可 / 更新
```

- 左导航：图标 + 名称；当前分区用强调色左侧 2px 条与浅底。
- 「全部」总览：六张分区卡两列排（1120 下），每张写当前预设/状态与一句说明；点卡进入分区。
- 右侧内容最大 760；分区标题只一行（标题 + 一句说明），不再有编号和眉标。
- 窄窗（<900）：左导航收成顶部下拉/图标栏，内容单列。

### 4.2 预设卡

每张预设是一块 72–84 高的卡：

```text
[图标]  队列优先                     ✓
        点歌加入队列，不替换正在放的
```

- 2–3 张一行；选中：强调色 1px 边 + 浅底 + 右侧勾。
- 点击立即应用整组字段（不弹确认）；顶部一行小字「已应用」1.2s 后淡出，或卡本身保持选中即可。
- 预设不写入新的 `presetId`：**当前值属于哪组就是哪组**，避免第二份状态。
- 当前值不匹配任何预设：显示一张「自定义」卡（选中），并保留自定义值。

### 4.3 自定义 sheet

- 每个分区右下角「自定义…」按钮（Outlined，34 高），打开 420 宽的右侧 sheet。
- sheet 内是现有的逐项控件（开关、下拉、输入、权重对话框入口），分组标题与当前设置卡一致。
- 改动即时生效；关闭 sheet 后按当前值重新判定预设选中。
- 不在 sheet 里放「保存」按钮：设置一直是即时生效的，按钮只会制造「未保存」的错觉。

### 4.4 快捷动作

不是所有东西都做成预设。分区里保留少量**动作按钮**：

| 分区 | 快捷动作 |
| --- | --- |
| 音乐库 | 立即扫描、添加文件夹、更改缓存上限 |
| 歌词 | 立即补齐、打开标记管理 |
| 桌面 | 设为默认播放器、安装桌面入口 |
| 关于 | 检查更新、查看许可 |

动作是按钮，不参与预设判定。

### 4.5 预设定义（首版）

| 分区 | 预设 | 字段 |
| --- | --- | --- |
| 外观 | 跟随系统 / 浅色 / 深色 | `themeMode` |
| 音乐库 | 自动扫描 / 手动 | `autoScanOnStartup` |
| 播放 | 队列优先 | `replaceQueueOnClick=false`、`favoritesDoubleClickPlays=true`、`onlyLikeOnDoubleClick=false`、`autoResumeOnStartup=true` |
| 播放 | 单曲优先 | `replaceQueueOnClick=true`、`favoritesDoubleClickPlays=true`、`onlyLikeOnDoubleClick=false`、`autoResumeOnStartup=true` |
| 播放 | 收藏优先 | `replaceQueueOnClick=false`、`favoritesDoubleClickPlays=false`、`onlyLikeOnDoubleClick=true`、`autoResumeOnStartup=true` |
| 歌词 | 手动 | `autoFill=false`、`gapCheckEnabled=false` |
| 歌词 | 平衡 | `autoFill=true`、`gapCheckEnabled=true` |
| 歌词 | 省电 | `autoFill=true`、`gapCheckEnabled=false` |
| 发现 | 关闭学习 / 开启学习 | `useListeningHistory` |
| 桌面 | 托盘常驻 / 关闭即退出 | `closeToTray` |

> 预设只设**行为字段**，不碰密钥、API 地址、模型名、文件夹路径这些「读者自己的东西」；它们只在自定义 sheet 里出现。

### 4.6 搜索与重置

- 设置页顶部一个搜索框（P3）：输入「托盘」「队列」「歌词」直接跳到分区并高亮对应控件。
- 右上 `⋯`：恢复本分区默认 / 恢复全部默认；恢复前弹一次确认。

## 5. 视觉

- 沿用 `CompactTokens`：控件 34、圆角 8、卡圆角 12、间距 8/12/16；不新增 token。
- 分区标题 20–24 宋体；说明 11–12 次级色；预设卡标题 13、说明 11。
- 每屏只有一个强调色元素：选中的预设卡 / 当前分区条；其余用中性色。
- 图标只出现在预设卡与快捷动作，开关行不再重复图标。
- 深浅色都按现有主题取色；对比度沿用 `theme_contrast_test`。

## 6. 状态与数据

| 状态 | 归属 | 持久化 |
| --- | --- | --- |
| 当前分区 | `SettingsPane` 本地 state 或路由 | 会话 |
| 主题/语言/播放/歌词/桌面字段 | `SettingsController`（现有） | 现有偏好键 |
| 当前预设 | **派生**（当前值与预设 bundle 比较） | 不存 |
| 搜索词 | `SettingsPane` 本地 state | 会话 |
| 缓存上限 | `libraryCacheLimitProvider`（现有） | 现有 |

- 不新增 `selectedPreset` 字段：预设是读法，不是事实。
- 自定义 sheet 直接调用现有 setter；不引入第二套配置。

## 7. 落地顺序

### S0 · 壳与导航
1. `SettingsPane` 两栏骨架 + 分区枚举 + 「全部」总览 + 窄窗回落。
2. 分区标题/说明；删编号与眉标。

### S1 · 预设卡与三个分区
3. `SettingsPresetCard` 共用组件；外观 / 音乐库 / 播放三组预设。
4. 自定义 sheet 壳；把现有播放开关移入。

### S2 · 歌词 / 发现 / 桌面
5. 歌词三预设 + 自定义 sheet（API/模型/预算）。
6. 发现、桌面预设与快捷动作。

### S3 · 搜索与重置
7. 设置搜索（分区 + 控件标题匹配）。
8. 恢复本分区/全部默认；确认弹窗。

### S4 · 收尾
9. 四语文案、空态/窄窗、截图与测试基准、文档与 AGENTS 地图。

## 8. 实施备注（2026-10-31）

- 已按本方案落地：左侧分区导航 + 「全部」总览、六区预设、每区自定义 sheet、设置搜索、恢复本区/全部默认（含确认）。
- 额外保留「音源健康」分区（无预设，卡片直达权重对话框）。
- 搜索按分区标题与说明匹配；关键词（如「托盘」）没有硬编码进界面，避免文案表之外的字符串。

## 8.1 仍待定

1. 智能歌词卡：拆成「预设 + 自定义 sheet」，还是保留现有整卡、只加预设入口？（推荐拆）
2. 「全部」总览的卡片是否显示每项当前值，还是只显示预设名？
3. 设置搜索是「过滤分区」还是「跳到分区并高亮控件」？（推荐后者）
4. 恢复默认是否需要二次确认？（推荐需要）

## 9. 不在范围

- 新增主题/强调色/密度等新设置项（只重排现有项）。
- 音源配置页（`/sources`）的重构。
- 移动端布局。
- 账号/云同步。

## 10. 验收

- 1120×760：每个分区一屏可见（歌词分区允许自定义 sheet 内滚动）。
- 900×600：导航收起、内容单列不溢出。
- 点预设立即生效；当前值不匹配任何预设时「自定义」选中。
- 自定义 sheet 改动即时生效；关闭后预设判定正确。
- 现有设置全部仍可达（没有因为紧凑而删掉任何字段）。
- `flutter analyze` 无 issue；`flutter test` 全绿；四语文案齐全。
