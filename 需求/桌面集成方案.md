# 桌面集成方案

> Linux 桌面的两条能力线：**后台播放**（MPRIS 系统媒体控制 + 系统托盘）与**默认播放器**
> （XDG 桌面项 + 启动参数 + 单实例转发）。
>
> 上位文档：[紧凑播放器重构方案](紧凑播放器重构方案.md)（架构现状与验收）、
> [队列模型方案](队列模型方案.md)（播放队列的模型）。
>
> 本文是实现前的评审稿。范围与本文不符时，先改本文。

## 1. 目标与范围

| 能力 | 用户视角的结果 |
| --- | --- |
| 后台播放 · MPRIS | GNOME / KDE 的系统媒体菜单里出现 Tune，显示封面与歌名；键盘媒体键能控制播放；别的程序（如 `playerctl`）能远程控制 Tune |
| 后台播放 · 托盘 | 托盘常驻图标，鼠标悬停显示当前歌名；关掉窗口后进程留在托盘里继续播放；托盘菜单能播放/暂停、切歌、唤回窗口、退出 |
| 默认播放器 | 文件管理器里音频文件的「打开方式」有 Tune；双击音频文件用 Tune 打开并播放；命令行 `tune a.mp3 b.flac` 能播放这些文件；已经是默认播放器时双击不会再开第二个进程 |

**范围**：仅 Linux 桌面（v1 验收平台）。Windows / macOS / Android / iOS / Web 走空实现，
接口留好扩展位，本次不实现 SMTC 与 NowPlaying。

**不在范围**：手机端通知栏控制、锁屏控制、开机自启、桌面歌词——这些在
[紧凑播放器重构方案](紧凑播放器重构方案.md) 第 4 节里已明确移出主链路，本次不捡回来。

## 2. 现状与缺口

| 能力 | 现在的实现 | 缺口 |
| --- | --- | --- |
| 播放状态 | `PlaybackController` / `PlaybackState`（`lib/features/player/`） | 状态齐全，但没有对外出口 |
| 系统媒体控制 | 无 | 没有 D-Bus 服务，系统不认识 Tune |
| 托盘 | 无 | 关窗口即退出，播放中断 |
| 桌面项 | `linux/cn.iouf.tune.desktop` | 没有 `MimeType`，`Exec=tune` 不带 `%U`，系统不会把音频文件交给它 |
| 启动参数 | 无 | `tune a.mp3` 里的路径被丢掉 |
| 多实例 | 无 | 双击两次音频文件会开出两个进程抢声卡 |

已经具备的条件：`just_audio_media_kit` 后端在 Linux 上工作正常；
`window_manager` 已能控制窗口显示与隐藏；`CrossPlatformMusicScanner.scanMusicFile`
能把单个文件变成 `Song`。

## 3. 分层落点

依赖方向沿用 [架构契约](../docs/architecture.md)：`presentation → application → data/services`。
播放状态仍然只有 `PlaybackController` 一个来源，桌面集成**只读**它、**不持有**它。

```text
lib/
├── data/services/
│   ├── mpris/
│   │   ├── mpris_service.dart          # 接口 + 快照模型（无平台依赖）
│   │   └── mpris_snapshot.dart         # 快照与曲目模型
│   ├── tray/
│   │   └── tray_service.dart           # 接口 + 菜单项模型
│   ├── desktop/
│   │   ├── audio_mime_types.dart       # 音频 MIME 列表（桌面项与 MPRIS 共用）
│   │   ├── default_player_service.dart # xdg-mime / 桌面项查询
│   │   ├── single_instance_service.dart # 抢占 cn.iouf.tune + 转发打开的文件
│   │   └── startup_files.dart          # 命令行里的文件
│   ├── impl/
│   │   ├── dbus_introspection.dart     # D-Bus 接口描述的小工具
│   │   ├── mpris/                      # D-Bus 实现（dbus 包）
│   │   │   ├── mpris_service_io.dart
│   │   │   ├── mpris_dbus_object.dart
│   │   │   ├── mpris_interfaces.dart   # 两个接口的描述
│   │   │   ├── mpris_properties.dart   # 属性表
│   │   │   └── mpris_values.dart
│   │   ├── tray/                       # StatusNotifierItem + dbusmenu 实现
│   │   │   ├── tray_service_io.dart
│   │   │   ├── tray_icon_object.dart
│   │   │   ├── tray_icon_interface.dart
│   │   │   ├── dbus_menu.dart
│   │   │   ├── dbus_menu_entry.dart
│   │   │   ├── dbus_menu_interface.dart
│   │   │   └── tray_icon_image.dart
│   │   └── desktop/                    # Linux 实现与空实现
│   └── providers/                      # Riverpod 装配
├── features/desktop/
│   └── application/
│       ├── desktop_integration_provider.dart  # 装配 controller，跟随设置与语言
│       ├── desktop_integration_controller.dart # 总装：起服务、订阅播放状态
│       ├── desktop_window.dart         # 窗口的显示、隐藏与退出
│       ├── mpris_state_mapper.dart      # 播放状态 → MPRIS 快照
│       ├── playback_track_tracker.dart  # 曲目编号
│       ├── tray_integration.dart        # 托盘菜单、提示与动作
│       ├── playback_mpris_backend.dart   # MPRIS 命令 → 播放动作
│       └── opened_files_handler.dart    # 打开的文件 → 扫描 → 播放
└── assets/icons/app_icon_tray.png      # 托盘图标素材
```

规则：

- service 不依赖 Riverpod，不 import `features/`。
- 平台差异按仓库既有做法成对实现 `*_io.dart` / `*_stub.dart`，用条件导入切换，
  Web 构建不碰 `dart:io`。
- MPRIS 与托盘都是**外部输入 → 播放动作**的适配器，落在 `features/desktop/application`，
  播放动作一律回调 `PlaybackController`，不自己改播放状态。
- 三样东西（MPRIS、托盘、单实例）都在**会话总线**上，用 `DBusClient.session()`；
  系统总线是给系统服务用的。

## 4. MPRIS 规格

### 4.1 名字与对象

| 项 | 值 |
| --- | --- |
| 总线名 | `org.mpris.MediaPlayer2.tune` |
| 对象路径 | `/org/mpris/MediaPlayer2` |
| 接口 | `org.mpris.MediaPlayer2`、`org.mpris.MediaPlayer2.Player` |
| 曲目 ID | `/org/mpris/MediaPlayer2/Track/<n>`，n 随曲目递增 |

用 `dbus` 包直接实现 D-Bus 服务（`mpris` 包限定 Dart 2，用不了）。

### 4.2 `org.mpris.MediaPlayer2`

| 方法 | 行为 |
| --- | --- |
| `Raise` | 显示并聚焦主窗口 |
| `Quit` | 退出应用 |

| 属性 | 值 |
| --- | --- |
| `Identity` | `Tune` |
| `DesktopEntry` | `cn.iouf.tune` |
| `SupportedUriSchemes` | `file`、`http`、`https` |
| `SupportedMimeTypes` | 与桌面项一致的音频 MIME 列表 |
| `CanRaise` / `CanQuit` | `true` |
| `HasTrackList` | `false` |

### 4.3 `org.mpris.MediaPlayer2.Player`

方法：`Play`、`Pause`、`PlayPause`、`Stop`、`Next`、`Previous`、
`Seek(x)`（微秒偏移）、`SetPosition(o, x)`（曲目 ID + 微秒绝对位置）、`OpenUri(s)`。

| 属性 | 来源 |
| --- | --- |
| `PlaybackStatus` | `PlaybackStatus.playing/paused/idle` → `Playing`/`Paused`/`Stopped` |
| `Metadata` | 当前曲目的标题、艺人、专辑、封面、时长、地址 |
| `Position` | `PlaybackState.position` |
| `Volume` | `PlaybackState.volume`（0.0–1.0） |
| `Rate` | `PlaybackState.speed` |
| `Shuffle` | 播放模式为随机时为 `true` |
| `LoopStatus` | 单曲循环 → `Track`；顺序与随机 → `Playlist`（队列到头会接回，所以是列表循环） |
| `CanPlay` / `CanPause` | 有当前曲目时为 `true` |
| `CanGoNext` / `CanGoPrevious` | 队列里不止一首时为 `true` |
| `CanSeek` | 曲目时长已知且不是直播流时为 `true` |
| `MinimumRate` / `MaximumRate` | `0.5` / `2.0`（与 `setSpeed` 的夹取范围一致） |

`Volume` 可写：外部改了音量就同步到 `PlaybackController`。
`Position` 只读，客户端轮询；拖动进度用 `SetPosition`。

属性变化时发 `org.freedesktop.DBus.Properties.PropertiesChanged`，
只发真正变了的字段，避免每个 position tick 都发信号。

## 5. 托盘规格

| 项 | 行为 |
| --- | --- |
| 协议 | `org.kde.StatusNotifierItem` + `com.canonical.dbusmenu`，走会话总线 |
| 图标 | `assets/icons/app_icon_tray.png`（64×64 素材，运行时缩成面板要的 22/24/32/48），随包发布，不依赖系统安装 |
| 悬停提示 | 当前歌名 `歌名 - 艺人`；没有歌时显示 `Tune` |
| 左键点击 | 显示并聚焦主窗口；窗口已显示时隐藏它 |
| 右键菜单 | 播放/暂停、上一首、下一首、显示主窗口、退出 |

托盘用纯 Dart 实现（`dbus` 包），不引入原生依赖：图标以 `IconPixmap`（ARGB 像素）送出去，
菜单以 dbusmenu 结构送出去，桌面自己画。

向面板登记时两套写法都试一遍：先按路径（`/StatusNotifierItem`）登记，这是 GNOME 的
`ubuntu-appindicators` 扩展认的写法；失败再按服务名 + 路径登记，这是 KDE 认的写法。

窗口关闭语义由设置项 `closeToTray` 决定（默认开）：

- 开：点关闭按钮 → 隐藏窗口，进程留在托盘，播放继续。
- 关：点关闭按钮 → 正常退出。

「退出」菜单项与 MPRIS 的 `Quit` 都会真正结束进程。

## 6. 默认播放器规格

### 6.1 桌面项

`linux/cn.iouf.tune.desktop` 补三处：

```ini
Exec=tune %U
MimeType=audio/mpeg;audio/mp3;audio/x-wav;audio/wav;audio/wave;audio/x-pn-wav;audio/flac;audio/x-flac;audio/ogg;audio/x-ogg;audio/opus;audio/mp4;audio/x-m4a;audio/aac;audio/x-aac;
```

- `Exec` 带 `%U`：一次可以接多个文件。
- `MimeType` 覆盖常见格式，和 `just_audio` 能解的格式对齐；这份列表的源头是
  `lib/data/services/desktop/audio_mime_types.dart`，桌面项与 MPRIS 的
  `SupportedMimeTypes` 都以它为准。
- 桌面项由 `linux/install-desktop-entry.sh` 装进 `~/.local/share/applications`；
  该脚本会把 `Exec` 改写成构建产物路径，改动后要一并保留 `%U`。

### 6.2 启动参数

启动时读进程自己的命令行（`/proc/self/cmdline`），挑出存在的文件路径（参数以 `-` 开头的是开关，丢掉），
逐个用 `CrossPlatformMusicScanner.scanMusicFile` 变成 `Song` 塞进队列并播放。

> 框架在 Linux 上不把命令行交给程序（`Platform.executableArguments` 是空的），所以读的是进程自己的命令行；
> 纯逻辑（挑出文件）放在 `lib/data/services/desktop/startup_files.dart`，读命令行的部分在实现层。

### 6.3 单实例

| 步骤 | 行为 |
| --- | --- |
| 1 | 启动时向总线申请 `cn.iouf.tune` |
| 2 | 申请成功 → 这是首个实例，注册 `cn.iouf.tune` 对象，对外提供 `OpenFiles(paths)` 与 `Activate()` |
| 3 | 申请失败 → 已有实例在跑，把命令行里的文件通过 `OpenFiles` 转发过去，然后自己退出 |
| 4 | 首个实例收到 `OpenFiles` → 走 6.2 的同一条路径打开文件，并 `Activate()` 把窗口唤到前面 |

首个实例在 `runApp` 之前就占住名字，避免两个进程同时认为自己才是首个。

## 7. 设置项

设置页新增一组「桌面集成」：

| 项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 关闭窗口时最小化到托盘 | 开关 | 开 | 关掉就退出 |
| 在系统媒体中心显示 Tune | 开关 | 开 | 关掉就释放 MPRIS 总线名 |
| 设为默认播放器 | 按钮 | —— | 调 `xdg-mime default cn.iouf.tune.desktop audio/mpeg`，不可用时禁用并说明原因 |

## 8. 依赖与构建

| 依赖 | 用途 | 备注 |
| --- | --- | --- |
| `dbus ^0.7.15` | D-Bus 客户端/服务端 | 纯 Dart；MPRIS、托盘、单实例都用它 |

托盘没有额外的原生依赖：不用 `tray_manager`，也不需要 `ayatana-appindicator3` 的开发包。
图标与菜单都是自己按协议发到会话总线上，构建产物里不夹带 C 库。

`dbus` 停在 0.7 线上，是因为 `file_picker` 还要 0.7；等它放开再一起升。

- [ ] `flutter build linux` 通过，程序能启动。
- [ ] `busctl --user introspect org.mpris.MediaPlayer2.tune /org/mpris/MediaPlayer2` 能看到两个接口。

- [ ] 媒体键能暂停与切歌。

- [ ] 点关闭按钮后窗口消失、进程还在、声音继续。
- [ ] `tune a.mp3` 能播放该文件；再次 `tune b.mp3` 时只有一个进程，窗口被唤到前面并播放 b。
- [ ] 文件管理器里音频文件的「打开方式」有 Tune。
- [ ] 设置里的三个新项行为正确，切语言后文案跟着变。
- [ ] Web 构建不被 `dart:io` 拖垮（`flutter build web` 通过）。
