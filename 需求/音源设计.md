# 音源设计

本文档记录 Tune 新播放器链路的音源模型、扩展方式与启动扫描策略。

## 1. 目标与范围

「音源」统一覆盖三类来源：

1. **本地目录**：复用 `CrossPlatformMusicScanner`，扫描用户配置的音乐文件夹。
2. **开放曲库**：无需账号的公共音频目录，内置 Openverse、Jamendo、Internet Archive。
3. **开放 API**：可自建的 JSON 服务，内置 NeteaseCloudMusicApi 适配器。

不执行 LX Music / MusicFree 的 JavaScript 插件脚本。需要新站点时，通过实现
`MusicSourceAdapter` 接入，而不是在运行时加载第三方脚本。

## 2. 分层与状态归属

```
settings UI / sources UI
        │
        ├── MusicSourcesController   （音源开关与配置的唯一来源）
        ├── SettingsController       （启动自动扫描开关）
        └── LibraryController        （歌曲列表、扫描进度、结果摘要）
                    │
                    ▼
            MusicSourceService      （并发编排、超时、按音源隔离失败）
                    │
                    ▼
            MusicSourceAdapter      （每个音源一个实现）
                    │
                    ▼
            MusicSourceStore        （配置与上次扫描时间的持久化）
```

约束：

- `MusicSourcesController` 只管理配置，不触发扫描。
- `LibraryController` 是歌曲列表的唯一事实来源，不持有音源配置副本。
- `MusicSourceService` 不依赖 Riverpod，便于单元测试与复用。
- 适配器只负责「拉取 + 映射为 `Song`」，不写持久化，不改 UI 状态。

## 3. 歌曲身份与播放 URL

远程歌曲使用两套字段：

- `uri`：稳定的规范身份，格式为 `tune://<sourceId>/<externalId>`。
- `streamUrl`：当前可直接播放的 HTTP(S) 地址，可能过期。
- `artworkUrl`：封面地址，可选。

播放时使用 `Song.playbackUri`：优先 `streamUrl`，为空时回退 `uri`。本地歌曲保持
`sourceId == null`、`streamUrl == null`，继续用文件路径播放，兼容旧音乐库。

远程歌曲的 `id` 由 `SourceSongFactory.stableId(uri)` 生成（FNV-1a，确定性），
同一首歌在多次扫描之间保持稳定，播放队列与收藏不会因刷新而错位。

## 4. 内置音源

| id | 名称 | 默认状态 | 配置 | 自动扫描间隔 |
| --- | --- | --- | --- | --- |
| `local` | 本地音乐 | 启用 | 音乐库扫描目录 | 每次启动 |
| `openverse` | Openverse | 启用 | 扫描关键词 | 6 小时 |
| `jamendo` | Jamendo | 关闭 | Client ID、关键词 | 6 小时 |
| `internet_archive` | Internet Archive | 启用 | 查询条件、数量 | 12 小时 |
| `netease` | 网易云音乐 API | 关闭 | API 地址、关键词、数量 | 3 小时 |

说明：

- Openverse 匿名接口有速率限制，因此默认 6 小时刷新一次。
- Jamendo 需要免费 Client ID；未配置时扫描结果为「需要配置」，不会报错。
- Internet Archive 会为每个搜索结果补拉条目元数据，默认只取 8 条，上限 20 条。
- Netease 适配器在扫描时调用 `/song/url/v1` 解析播放地址，失败时回退 `/song/url`。
  播放地址过期后，下一次自动扫描会刷新。

## 5. 启动自动扫描

启动流程：

1. `AppInitializer` 初始化持久化、播放器与扫描器。
2. `appInitializationProvider` 完成后再调度自动扫描。
3. `LibraryController` 先加载缓存歌曲，保证首帧可用。
4. 缓存就绪后调用 `scan(localPaths, auto: true)`，并发扫描所有已启用音源。

行为约定：

- 自动扫描不阻塞首帧；扫描期间继续展示缓存。
- 远程音源在间隔内返回 `skipped`，保留缓存歌曲。
- 成功音源用新结果替换自己的旧歌曲；失败或未配置音源保留自己的缓存歌曲。
- 被关闭的音源不再出现在扫描结果中，其缓存歌曲会从当前库移除。
- 单个音源失败不影响其他音源；所有失败会在状态栏与音源列表中标出。

开关保存在 `auto_scan_on_startup`，默认开启。

## 6. 持久化

| Key | 内容 |
| --- | --- |
| `music_sources_v1` | 音源配置列表（开关与 settings） |
| `music_source_last_scan_v1` | 各音源上次成功扫描时间 |
| `custom_scan_paths` | 本地扫描目录 |
| 音乐库存储 | 扫描后的 `Song` 列表，包含远程字段 |

扫描时间在歌曲列表成功写入后提交；若音乐库保存失败，不会标记该音源为“已扫描”，
下次启动会自动重试，避免出现“有时间戳但没有歌曲”的状态。

读取配置时以内置定义为基础合并用户保存值，因此新增内置音源或修改默认文案
不需要迁移旧数据；未知的自定义音源条目会被保留。

## 7. 扩展一个新音源

1. 在 `lib/data/services/music_sources/` 新建适配器，实现 `MusicSourceAdapter`：
   - `sourceId`
   - `isConfigured`
   - `configurationHint`
   - `configurationFields`（设置对话框渲染的字段）
   - `autoScanInterval`
   - `scanTimeout`
   - `scan(...)`
2. 在 `MusicSourceService` 的适配器表中注册。
3. 在 `BuiltInMusicSources.defaults` 增加默认配置。
4. 为 JSON 映射补充纯函数测试，避免测试依赖网络。

适配器内部建议：

- 用 `SourceSongFactory.normalizeUrl` 过滤非 HTTP(S) 地址。
- 用 `SourceSongFactory.create` 生成 `Song`，保证 id、uri 规则一致。
- 捕获网络与解析异常并返回 `failedResult`，不要向上抛。

## 8. 已知限制

- 不运行 LX Music / MusicFree JS 插件；新增站点需要写 Dart 适配器。
- 远程播放依赖网络，当前没有下载与离线缓存流程。
- Openverse 匿名配额有限；高频手动扫描可能收到 429。
- Netease 适配器只面向自建服务，不内置任何账号或第三方公共服务地址。
- 远程封面使用 `Image.network`，失败时显示占位图。
