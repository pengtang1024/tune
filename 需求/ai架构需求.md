# Tune 音乐播放器项目全量整合文档（含所有对话结果）

## 一、项目核心定位

Tune 是一款基于 Flutter 的跨平台全功能本地音乐播放器，覆盖 Android/iOS/Windows/macOS/Linux/Web 六大平台，核心目标：
*   **功能完整**：覆盖音频播放、音乐库管理、歌词同步、播放列表等全场景需求；
*   **体验一致**：视觉与操作逻辑跨平台统一，适配各平台特性（移动端后台播放、桌面端快捷键等）；
*   **技术可靠**：轻量包体（移动端≤20MB）、快速启动（≤2 秒）、稳定播放，代码架构清晰可维护。

## 二、架构设计与目录结构

### 1. 分层架构（Clean Architecture + Riverpod）

| 层级        | 核心职责      | 技术载体                                           | 设计原则                                                                  |
| --------- | --------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| **UI 层**  | 界面渲染与用户交互 | 页面（Pages）、组件（Widgets）                          | 页面仅做布局组合，组件按单一职责拆分（≤200 行 / 文件），不包含业务逻辑。                              |
| **状态层**   | 管理状态与业务逻辑 | `StateNotifier`、`Provider`（`flutter_riverpod`） | 状态模型（`freezed`生成不可变数据）与逻辑分离，通过`ref.watch`实现 UI 与状态解耦。                 |
| **领域层**   | 核心实体与业务规则 | 实体（Song/Playlist）、用例（PlaySongUseCase）          | 纯 Dart 代码，独立于框架，封装单一业务逻辑（如扫描、播放控制）。                                   |
| **数据层**   | 数据获取与存储   | 仓库（Repository）、数据源（本地 / 远程）                    | 通过 Repository 模式隔离数据源，隐藏存储细节（`hive`/`shared_preferences`）。            |
| **核心服务层** | 全局通用能力    | 音频服务、扫描服务、网络服务、权限服务                            | 封装跨模块逻辑：音频解码（`just_audio`）、文件扫描、`dio`网络请求、权限管理（`permission_handler`）。 |
| **平台适配层** | 隔离平台差异    | 原生通道、平台服务                                      | 处理移动端后台播放（`audio_service`）、桌面端窗口管理、Web 端浏览器限制。                        |

## 五、UI 组件拆分规范（所有对话确认的规则）

### 1. 拆分原则

*   **单一职责**：1 个组件仅负责 1 个功能（如`progress_bar.dart`仅处理进度显示与拖拽）。
*   **行数控制**：单个组件文件≤200 行，超则拆分关联子组件（如控制栏拆分为按钮 + 模式切换）。
*   **状态隔离**：组件仅通过`onXxx`回调暴露交互，业务逻辑由`provider`处理，不内置状态管理。
*   **复用优先**：多模块复用的组件放`通用组件`目录；模块专属组件放`业务模块/[模块]/widgets`目录。
