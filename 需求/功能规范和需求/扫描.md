# 扫描功能需求规范（基于单一职责与解耦架构）

## 一、核心功能定位
全局扫描功能负责跨平台检索指定目录下的音频文件，提取并解析元数据，支持配置管理与结果筛选，最终为音乐库提供可持久化的音频信息数据。


## 二、状态层设计（`states`目录）

### 1. 扫描配置状态模型（`scan_config_state.dart`）
- 存储内容：
  - 各平台默认目录路径集合（按平台区分）
  - 自定义目录路径集合
  - 扫描范围配置（是否包含子目录等）
- 核心方法：`copyWith`用于更新配置，`initial`静态方法初始化默认配置

### 2. 扫描配置管理器（`scan_config_state_notifier.dart`）
- 职责：仅处理配置相关逻辑
  - 新增/移除自定义目录
  - 重置平台默认目录
  - 更新扫描范围配置
- 依赖注入：通过`Ref`获取存储服务（用于持久化配置）

### 3. 扫描过程状态模型（`scan_process_state.dart`）
- 存储内容：
  - 扫描状态（未开始/进行中/已完成/失败）
  - 扫描进度（百分比）
  - 已发现音频文件数量
  - 错误信息（若失败）
- 核心方法：`copyWith`用于更新状态，静态构造方法表示不同扫描阶段

### 4. 扫描过程管理器（`scan_process_state_notifier.dart`）
- 职责：仅处理扫描执行逻辑
  - 启动/终止扫描任务
  - 更新扫描进度
  - 处理扫描异常
- 依赖注入：通过`Ref`获取配置数据、文件扫描服务、元数据解析服务

### 5. 扫描结果状态模型（`scan_result_state.dart`）
- 存储内容：
  - 音频文件列表（包含基础信息与标签数据）
  - 筛选条件
  - 已选择待导入文件ID集合
- 核心方法：`copyWith`用于更新结果数据

### 6. 扫描结果管理器（`scan_result_state_notifier.dart`）
- 职责：仅处理结果相关逻辑
  - 添加/清空扫描结果
  - 应用筛选条件
  - 选择/取消选择文件
  - 导入选中文件到音乐库
- 依赖注入：通过`Ref`获取音乐库服务、存储服务


## 三、提供者层设计（`providers`目录）

### 1. 扫描配置提供者（`scan_config_providers.dart`）
- 仅定义：`final scanConfigProvider = StateNotifierProvider<ScanConfigStateNotifier, ScanConfigState>(...)`
- 作为配置数据访问的唯一入口

### 2. 扫描过程提供者（`scan_process_providers.dart`）
- 仅定义：`final scanProcessProvider = StateNotifierProvider<ScanProcessStateNotifier, ScanProcessState>(...)`
- 作为扫描状态与进度访问的唯一入口

### 3. 扫描结果提供者（`scan_result_providers.dart`）
- 仅定义：`final scanResultProvider = StateNotifierProvider<ScanResultStateNotifier, ScanResultState>(...)`
- 作为扫描结果与选择状态访问的唯一入口


## 四、UI层设计（`widgets`目录）

### 1. 配置相关功能组件
- `scan_directory_item.dart`：单一职责为展示/编辑单个目录项
- `platform_directory_section.dart`：单一职责为展示平台默认目录组
- `custom_directory_list.dart`：单一职责为展示/管理自定义目录列表
- `directory_picker_button.dart`：单一职责为处理目录选择交互

### 2. 扫描控制相关功能组件
- `scan_button.dart`：单一职责为处理扫描启动/停止交互
- `scan_progress_indicator.dart`：单一职责为展示扫描进度
- `scan_status_display.dart`：单一职责为展示当前扫描状态

### 3. 结果处理相关功能组件
- `audio_file_item.dart`：单一职责为展示单个音频文件信息
- `audio_tag_display.dart`：单一职责为展示音频文件的标签数据
- `file_filter_panel.dart`：单一职责为处理筛选条件设置
- `selection_controls.dart`：单一职责为处理文件选择（全选/反选）
- `import_button.dart`：单一职责为处理导入到音乐库交互

### 4. 页面组件
- `scan_settings_page.dart`：仅组合配置相关组件，搭建扫描设置页面布局，处理页面级空状态
- `scan_results_page.dart`：仅组合扫描控制与结果处理组件，搭建扫描结果页面布局，处理加载/完成状态切换


## 五、数据处理规范

### 1. 元数据解析
- 基础信息：标题、副标题、作者、专辑（单独字段存储）
- 扩展信息：歌词、流派、比特率等（统一以键值对形式存入`tags`字段）

### 2. 持久化范围
- 必须持久化：所有元数据（基础信息+扩展标签）、文件路径、扫描配置
- 无需持久化：原始音频文件、临时扫描状态（如实时进度）

### 3. 依赖注入设计
- 扫描服务：封装跨平台文件系统访问逻辑，通过`fileScannerProvider`提供
- 元数据解析服务：封装音频标签解析逻辑，通过`metadataParserProvider`提供
- 存储服务：封装数据持久化逻辑，通过`storageServiceProvider`提供


## 六、解耦与单一职责保障
1. 扫描配置变更时，仅`scan_config_state_notifier.dart`需要修改
2. 更换元数据解析库时，仅需修改解析服务实现，不影响UI与状态层
3. 调整筛选逻辑时，仅`scan_result_state_notifier.dart`与`file_filter_panel.dart`需要修改
4. 页面布局调整时，仅对应`page`组件需要修改，不影响功能逻辑
5. 所有功能组件仅依赖与其直接相关的1-2个provider
