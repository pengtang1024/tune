UI 组件拆分规范（基于单一性原则）
一、核心拆分原则
所有 UI 页面必须按 “单一职责” 拆分为最小粒度的功能组件，遵循 “一个组件只做一件事” 原则：
禁止出现 “万能组件”（如同时处理展示、交互、筛选的大型列表组件）。
页面组件仅负责布局组合，不包含具体 UI 细节或逻辑；功能组件专注单一功能，可独立复用。
二、扫描与配置类页面拆分
1. 扫描设置页面拆分
   核心功能组件（单一职责）：
   PlatformDirTitle：仅负责展示 “平台默认目录” 标题文本，无交互。
   DefaultDirItem：仅展示单个平台默认目录路径，附带 “重置” 按钮（点击触发目录重置）。
   CustomDirAddButton：仅负责 “添加自定义目录” 的点击交互，不处理目录选择逻辑（调用目录选择组件）。
   CustomDirItem：仅展示单个自定义目录路径，附带 “删除” 按钮（点击触发目录移除）。
   SubDirSwitch：仅负责 “包含子目录” 的开关 UI 与状态同步，不处理配置存储。
   页面组件（仅组合）：
   ScanSettingsPage：通过Column组合上述组件，添加页面标题和基础布局间距，不包含任何功能逻辑。
2. 音乐库扫描页面拆分
   核心功能组件（单一职责）：
   ScanTriggerButton：仅负责 “开始 / 停止扫描” 的按钮 UI 与点击交互（触发扫描服务）。
   ScanProgressBar：仅展示扫描进度百分比与进度条，通过扫描状态更新 UI。
   ScanStatusText：仅展示当前扫描状态文本（如 “扫描中... 已发现 100 首歌曲”）。
   FilterLabel：仅展示 “筛选条件” 标题文本，无交互。
   FilterDropdown：仅负责单个筛选条件（如按格式 / 专辑）的下拉选择 UI，不处理筛选逻辑。
   AudioFileItem：仅展示单首扫描歌曲的基础信息（标题、作者），附带选择复选框。
   SelectAllCheckbox：仅负责 “全选 / 取消全选” 的复选框 UI 与状态同步。
   ImportButton：仅负责 “导入选中歌曲” 的按钮 UI 与点击交互（触发导入服务）。
   页面组件（仅组合）：
   MusicLibraryScanPage：通过ListView+Column组合上述组件，区分 “扫描控制区”“筛选区”“结果列表区” 布局，不处理任何业务逻辑。
   三、播放控制类页面拆分
1. 播放器页面拆分
   核心功能组件（单一职责）：
   NowPlayingTitle：仅展示当前播放歌曲的标题文本，无交互。
   NowPlayingArtist：仅展示当前播放歌曲的作者文本，无交互。
   AlbumCoverImage：仅展示专辑封面图片，支持点击放大（无其他功能）。
   PlayPauseButton：仅负责播放 / 暂停按钮的 UI 与点击交互（触发播放服务）。
   PreviousButton：仅负责上一首按钮的 UI 与点击交互（触发播放服务）。
   NextButton：仅负责下一首按钮的 UI 与点击交互（触发播放服务）。
   ProgressSlider：仅负责播放进度滑块的 UI 与拖动交互（同步播放进度）。
   ProgressTimeText：仅展示当前播放时间 / 总时长文本（如 “1:30 / 3:45”）。
   VolumeButton：仅负责音量按钮的 UI 与点击交互（触发音量面板显示）。
   VolumeSlider：仅负责音量滑块的 UI 与拖动交互（同步音量状态）。
   页面组件（仅组合）：
   PlayerPage：通过Column+Stack组合上述组件，搭建播放器整体布局（封面区、信息区、控制区、音量区），不包含播放逻辑。
2. 播放列表页面拆分
   核心功能组件（单一职责）：
   PlaylistTitle：仅展示 “播放列表” 标题文本，无交互。
   SongItem：仅展示单首歌曲的标题、作者与序号，支持点击选中（触发歌曲切换）。
   EmptyPlaylistText：仅在播放列表为空时展示提示文本，无交互。
   ShuffleButton：仅负责 “随机播放” 按钮的 UI 与点击交互（触发播放模式切换）。
   页面组件（仅组合）：
   PlaylistPage：通过ListView组合上述组件，添加顶部标题栏与底部控制按钮布局，不处理列表数据逻辑。
   四、用户相关页面拆分
1. 用户中心页面拆分
   核心功能组件（单一职责）：
   UserAvatar：仅展示用户头像图片，支持点击更换（无其他功能）。
   UserNameText：仅展示用户昵称文本，无交互。
   UserEmailText：仅展示用户邮箱文本（如需），无交互。
   SettingItem：仅展示单个设置项（如 “账号安全”“主题设置”）的图标 + 文字 UI，支持点击跳转。
   LogoutButton：仅负责 “退出登录” 按钮的 UI 与点击交互（触发登出服务）。
   页面组件（仅组合）：
   UserCenterPage：通过Column+ListView组合上述组件，区分 “个人信息区”“设置列表区”“操作区” 布局，不处理用户数据逻辑。
   五、拆分后核心优势
   可维护性：修改某一 UI 细节（如按钮颜色、字体大小）时，仅需改动对应功能组件，不影响其他部分。
   可复用性：细小组件可跨页面复用（如VolumeSlider可同时用于播放器页面和设置页面）。
   测试便捷性：单一功能组件测试目标明确（如仅测试PlayPauseButton的点击交互是否触发状态变化）。
   协作效率：多人开发时，可按组件分工（如一人负责AlbumCoverImage，一人负责ProgressSlider），减少冲突。
   通过极致拆分，确保每个 UI 组件职责清晰、代码精简，从根本上避免 “牵一发而动全身” 的维护难题。
