请基于以下需求，设计并生成一个全平台 Flutter 音乐播放应用的详细实现方案，包括架构设计、核心功能开发、跨平台适配及技术细节。
一、应用定位与核心目标
开发一款支持 Android、iOS、Windows、macOS、Linux 和 Web 全平台的轻量级音乐播放应用，主打「本地音乐优先 + 在线资源融合」的混合体验，兼顾离线可用性与云端同步功能。核心目标是：跨平台体验一致、性能轻量、UI 现代简约，且支持高度个性化定制。
二、架构设计要求
分层架构：严格遵循 Clean Architecture 分层思想，明确划分：
表现层（Presentation）：页面、UI 组件、BLoC 状态管理、路由；
领域层（Domain）：核心实体（歌曲、播放列表、用户等）、仓库接口、业务用例；
数据层（Data）：仓库实现、本地 / 远程数据源、数据模型（DTO）；
核心层（Core）：基础服务（音频、存储、网络等）、工具类、常量、全局配置。
状态管理：使用 flutter_bloc 管理状态，区分「全局状态」（应用设置、播放状态、用户信息）和「局部状态」（页面交互、表单输入），通过事件流处理用户操作与系统事件。
模块化设计：采用插件化 / 模块化架构，确保各功能模块低耦合（如音频播放、音乐库、用户系统可独立扩展），支持按需加载。
三、核心功能模块需求
1. 音频播放核心模块
   基础功能：播放、暂停、上一首 / 下一首、进度拖拽、音量调节；
   进阶功能：后台播放（全平台）、音频焦点管理（避免被其他应用中断）、播放速度调节、音质选择；
   体验优化：支持耳机线控 / 蓝牙设备控制、系统媒体中心集成（如锁屏歌词、通知栏播放器控件）；
   技术要求：基于 just_audio 实现核心播放逻辑，封装 AudioPlayerService 统一管理播放状态。
2. 音乐库模块（本地 + 在线融合）
   本地音乐：通过 on_audio_query 获取设备本地音乐文件（支持歌曲、专辑、艺术家分类），自动解析元数据（标题、封面、歌词、时长）；
   在线资源：支持通过 API 拉取在线音乐推荐、榜单，支持在线播放与缓存；
   离线优先：无网络时自动切换「本地模式」，仅展示已缓存 / 本地音乐，确保基础功能可用；
   搜索与筛选：支持按歌名、艺术家、专辑搜索，支持按播放频率、最近添加排序。
3. 播放列表模块
   本地管理：支持创建、命名、编辑、删除播放列表，支持添加 / 移除歌曲、调整歌曲顺序；
   数据存储：未登录时用 Hive 本地存储播放列表（支持加密可选），确保数据仅保存在设备；
   云端同步：登录后自动同步播放列表到云端，支持多设备数据一致（需区分「本地私有列表」和「云端同步列表」）；
   体验细节：支持「最近播放」「喜欢的歌曲」等系统默认列表，支持列表导出 / 导入。
4. 用户模块（轻量化设计）
   状态模式：默认「游客模式」，无需登录即可使用核心功能（本地音乐播放、本地播放列表管理），数据仅本地持久化；
   登录功能：支持第三方登录（QQ,微信优先,可选 支付宝,抖音,GitHub,Facebook,Google、Apple,钉钉,微博等 ），登录后解锁云端同步（播放列表、收藏、播放历史）；
   数据隔离：游客模式数据保存在本地 Hive/SQLite，登录后触发「本地→云端」单向合并（不覆盖云端数据），登出后保留本地数据；
   隐私控制：支持关闭云端同步，手动选择需要同步的内容（如仅同步播放列表，不同步播放历史）。
5. UI/UX 模块
   响应式设计：适配不同屏幕尺寸（移动端全屏、桌面端窗口化、Web 端响应式布局）；
   主题系统：支持浅色 / 深色模式自动切换，提供至少 3 套预设主题（如极简灰调、活力轻电、暗夜星空），支持用户自定义主色调、圆角风格；
   视觉增强：歌词实时同步（LRC 解析 + 逐句动画）、音频可视化效果（频谱动画）；
   交互细节：卡片悬停效果、平滑过渡动画、下拉刷新 / 上拉加载，符合各平台设计规范（移动端遵循 Material/Cupertino，桌面端强化窗口交互）。
   四、跨平台适配要求
1. 移动端（Android/iOS）
   后台能力：支持后台持续播放，锁屏界面显示歌曲信息与控制按钮；
   系统集成：通知栏常驻播放器控件（支持暂停 / 切歌）、支持 Android 媒体会话 /iOS 媒体中心集成；
   权限管理：动态申请存储权限（Android）、媒体库访问权限（iOS），无权限时引导用户开启。
2. 桌面端（Windows/macOS/Linux）
   窗口设计：支持窗口大小调整、最小化到系统托盘（托盘显示当前播放歌曲，支持右键快捷控制）；
   快捷键：支持全局快捷键（如 Ctrl+Space 播放 / 暂停、Ctrl+→ 下一首）；
   系统集成：macOS 菜单栏显示播放状态、Windows 任务栏缩略图控制。
3. Web 端
   响应式布局：适配桌面浏览器与移动浏览器，支持全屏 / 窗口化切换；
   PWA 支持：实现离线缓存、添加到桌面功能，优化加载速度；
   浏览器兼容：处理 Web 音频自动播放限制（需用户交互后触发首次播放），适配主流浏览器（Chrome、Firefox、Safari）。
   五、现代化体验补充需求
   离线缓存优化：在线歌曲支持手动 / 自动缓存，缓存文件可管理（清理过期缓存、设置缓存上限）；
   个性化推荐：基于本地播放历史（游客模式）或云端数据（登录模式），推荐相似风格歌曲；
   多语言支持：内置中文、英文，支持动态加载新语言包（JSON 格式），支持热更新与版本管理；
   性能监控：低功耗设计（减少后台资源占用），避免播放卡顿、界面掉帧。
   六、技术栈要求
   核心框架：Flutter 3.10+；
   音频播放：just_audio + audio_service（后台播放）；
   状态管理：flutter_bloc + equatable；
   本地存储：Hive（播放列表、设置）+ shared_preferences（轻量配置）；
   网络请求：dio + 拦截器（请求 / 响应处理、API 版本控制）；
   路由管理：auto_route（类型安全路由）；
   本地音乐获取：on_audio_query；
   权限管理：permission_handler；
   后台任务：workmanager（Android）+ background_fetch（iOS）；
   UI 工具：flutter_screenutil（尺寸适配）+ custom_theme（主题封装）；
   多语言：flutter_localizations + 自定义语言包管理。
   七、测试与扩展要求
   测试策略：提供单元测试（领域层用例、工具类）、集成测试（模块交互）、跨平台测试矩阵（覆盖各平台核心场景）；
   扩展性：支持 API 版本兼容（通过拦截器实现）、主题配置扩展（用户自定义参数）、功能模块插件化（如后续添加 Podcast 支持）；
   稳定性：处理边缘场景（如音频文件损坏、网络中断、权限被拒），避免崩溃，提供友好错误提示。
