# Tune 项目架构需求文档

## 1. 项目概述

### 1.1 项目背景
Tune 是一款专注于提供简洁直观界面的跨平台音乐播放器应用，旨在帮助用户管理和播放本地音乐库。

### 1.2 目标用户
- 喜欢整理和播放本地音乐的用户
- 需要高质量音频播放体验的音乐爱好者
- 希望在多个平台上保持一致体验的用户（Android、iOS、Windows、macOS、Linux、Web）

### 1.3 核心问题
- 提供高质量音频播放支持（MP3、FLAC、WAV、AAC 等格式）
- 管理本地音乐库并支持元数据解析
- 提供跨平台一致的播放体验
- 支持多语言和多主题，满足个性化需求
- 提供歌词同步、智能搜索、播放列表管理等功能

## 2. 系统功能

### 2.1 主要功能
- **高质量音频播放** - 支持多种音频格式，提供流畅播放体验
- **本地音乐管理** - 自动扫描并整理本地音乐库
- **播放控制** - 播放/暂停/停止/上一首/下一首，支持进度拖拽、音量调节、播放速度调节
- **播放列表** - 创建和管理自定义播放列表，支持多种播放模式（列表循环、单曲循环、随机播放）
- **歌词同步** - LRC 格式歌词实时同步显示
- **智能搜索** - 支持按歌曲名、艺术家、专辑、流派等元数据快速搜索
- **多主题支持** - 8 种主题（潮流轻电、极简灰调、自然森系等），支持深色/浅色模式切换
- **多语言支持** - 支持中文、英文、日文、韩文、俄文等语言
- **响应式设计** - 适配不同屏幕尺寸，支持移动端和桌面端
- **后台播放** - 支持通知栏控制和锁屏控制
- **音效调节** - 提供均衡器调节功能
- **离线缓存** - 支持在线音乐缓存
- **智能推荐** - 基于播放历史的个性化推荐
- **个性化设置** - 字体、主题、播放设置等丰富选项

## 3. 技术架构

### 3.1 架构图
采用 **Clean Architecture + Riverpod 模式**，确保代码可维护性和扩展性。

### 3.2 设计模式
- **Clean Architecture** - 分层架构，分离业务逻辑与平台实现
- **Riverpod** - 状态管理，使用 `flutter_riverpod`
- **依赖注入 (DI)** - 使用 `get_it` 实现模块间解耦
- **路由管理** - 使用 `go_router` 实现导航
- **国际化** - 使用 `flutter_localizations`

### 3.3 主要组件交互
- UI 层通过 Riverpod 与业务逻辑层通信
- 业务逻辑层通过 Repository 模式与数据层交互
- 数据层通过 Platform Channel 与原生平台交互（如文件扫描、权限请求）

## 5. 开发环境



## 6. 技术约束

### 6.1 性能要求
- 支持流畅播放多种音频格式
- 快速扫描本地音乐库
- 后台播放优化（尤其在移动端）

### 6.2 安全要求
- 用户数据本地存储，不强制要求网络连接
- 使用 `shared_preferences` 和 `hive` 本地加密存储敏感信息（如用户会话）

### 6.3 已知问题
- Web 端音频播放限制（浏览器策略）
- 某些桌面平台的音频格式支持不完整

### 6.4 代码规范
- 使用 Flutter 官方编码规范
- 使用 `analysis_options.yaml` 配置静态分析规则

### 6.5 其他限制
- 当前仅支持本地音乐库管理，不提供云端同步功能（未来可扩展）
